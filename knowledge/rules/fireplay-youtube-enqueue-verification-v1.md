# Fireplay：YouTube自动上传受理必须有真实证据

用户2026-10-29重申：上传必须开启YouTube自动上传，并补传当前素材库中罗晨钧上传而没有YouTube链接的视频。原固定提交话术已经写明这项要求；本版补齐可核验门禁，不将入库成功解释为任务创建成功。

1. 入库/共享/名称/标签/设计师与需求绑定分别核对。顶层`VedioSouce=YouTube`表达请求意图；R2直传成功、素材ID、已勾选开关、`postProcessStatus=done`或本地requested标记，均不能单独证明平台受理了YouTube上传。
2. 读取真实当前素材详情与其当前视频资源。已有该资源的真实YouTube链接即可；否则取得精确material_id、video_resource_id、真实task_id与已受理状态的任务回执。保存原始响应，经`fireplay-youtube-handoff`绑定原视频哈希。账号路由仍由平台管理，不新增账号组截图门禁。
3. 未取得受理证据时，入库及绑定结果保留，任务明确为`needs_youtube_enqueue`，不得整项结案。通过平台支持的已有素材上传/重试入口补传，保留素材ID、需求关联、设计师与标签。现有MCP若仅能入库和查询，改走已授权原生页面；没有支持的入口就保留准确缺口，不臆造参数、任务或成功回执。
4. 用户本次授权补传无链接历史视频；先核对原任务，有已受理/进行中的任务则恢复原任务，unknown先查证。缺少链接不能据此无限重试、重复入库或删除旧记录。没有真实受理时不能以“交给平台”提前停止。
5. 真实初始受理后，执行与后续进度交Fireplay；不把排队当上传完成，不因向量化或缺少最终链接重入库。原不持续跟踪YouTube进度的约定继续适用于已受理任务。
