# Fireplay 自动提交与经验收尾

适用于已承接的翻译需求产生完整成片、聊天停在本地交付或需要恢复已有提交的情况。用户2026-10-27最新明确：每次上传后不跟踪YouTube进度，相信Fireplay平台。机器来源为config/fireplay-publication.json.completion。本版替代先前持续跟踪YouTube的建议，历史查询与失败记录原样保留。

1. 仅有本地成片：继续实际审核最新版，核对完整翻译、必需配音、字幕和正常播放效果。普通小瑕疵按当前发布审查接受；严重或问题过多仍阻断。未审核是下一项工作，不是永久停止理由。用户具体认可只适用于明确成片哈希，不改写旧revise、旧质量异议或公司默认。
2. 符合发布条件：直接执行已授权固定回传，不再次询问KIE或固定提交同意。逐需求独立聊天和费用；原片编号、语种和成片哈希绑定真实提交。
3. 初次提交：核对明确选中的需求组YouTube账号、实际任务/请求归属，以及素材名称、语言/产品tag、共享范围和需求绑定。共享组、上传人组、YouTube账号组与任务组是不同事实；shared_dept_id不能指定账号。连接器缺字段时用实际支持的显式账号网页路径，不编造参数。
4. Fireplay已受理、素材已入库且绑定核验完成：保存回执，直接经验收尾。后续YouTube排队、账号限额、向量化或是否已出现链接交给Fireplay，不轮询、不等全部完成、不为缺链接再次入库。对外如实报告“已提交Fireplay/已请求自动上传”，不冒称YouTube已上传。
5. 旧手工回传与不同操作者：按真实素材ID、源/成片字节及绑定回执识别已提交记录。网页和MCP身份可能不同，MCP本人任务列表为空不能证明平台未受理；不能据此重入库。已成功绑定的历史素材保留，不再因YouTube尾项发起补提、替换或删除。
6. 外部调用超时/unknown或绑定尚未核实：只恢复该次确切请求，核实是否被平台受理；这是提交确认，不是上传后的进度追踪。先查实际记录，不重复写。原审批拒绝仍保留，不能用新轮询伪装为批准。

经验收尾须提炼真实发现和失败签名，保留原scope与证据来源。重复经验关联既有知识，空白占位不进入方法召回；案例、ASR和账本是证据，不反复当新经验。按knowledge-review审查，再用candidate-archive保留原文和指纹归档；不能只为了清空队列而宣称质量通过。

结案按maintain RUN --close核验交付、知识和账本。未知费用、活动锁、被引用资产或缺必要证据时保留现场并报告具体原因；知识已总结不代表可以删除生产数据。

证据：evidence:review。本条由当前用户最新收尾要求和实际聊天/回执的开发者复盘支持，不是新增投放、费用或公司视觉标准授权。
