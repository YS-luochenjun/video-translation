# 无字底片与动画还原的制作门禁

来源：2026-10-20 用户指出同源六语视频均出现色块、英文残留和动画简化，要求先验证短片、再扩展六语，并积累知识避免重复。这里启用的是检查与阻断要求；本次运动背景修复没有通过，不把失败算法写成成功配方。

## 先检查无字底片

1. 分别查看原片、无字底片、透明译文字层和最终合成。不得用译文、模糊条或色块遮住残字后判断去字成功。共享底片未通过时停止各语言批量制作。
2. 擦除清单覆盖原字的完整进场、缩放、位置变化、描边、发光和出场，包含首末帧。OCR 空结果不等于没有文字；不能让边界帧的旧字进入时序传播的参考背景。
3. 干净参考帧须同时满足无字、无旧光晕、物体姿态相容。后面的无字帧中新增了苹果、手势或不同衣领形状，不能直接回填到早期。光流、配准及无缝融合只提供候选；缺少可见约束的手指、头发和腕部仍可能恢复错误。
4. 单独检查文字残留、纹理与颜色、前景几何与运动、时间边界。特别检查衣服褶皱、头发、手指、苹果边缘和光晕区域；OCR 检不出字不能代替这些检查。
5. 从实际编码的短片抽取密集边界帧，并审查连续运动。短片未通过时，保留失败对比、未解问题和成本，不导出六语版本冒充新成品。以两轮有界返工为限；需要换输入或更换修复路线时重新说明证据与约束。

## 动画是独立交付要求

- 建立源动画清单，记录文字的字体类别、行分组、白色/强调色切换、描边、光晕、缩放、位移和进出场；同时记录表情、箭头、按钮及其前后遮挡关系。
- 译文使用真实目标文字系统及共同口播定稿。按实际目标配音确定字词或短语时间，在此时间轴上重建源动画风格；不能用固定位置、统一颜色、整句出现替代原动画后仍声称保留效果。
- 装饰图形保留了像素不代表还原完成。核对图形内容、动画、时间、语义关联与层级；语义关联口播的图形须核对译后节奏，独立 CTA 按场景事件处理。
- 无字底片通过后先做一个语言的完整编码样片，检查视觉、动画、字形和视听同步，再扩展其他语言。各语言仍分别检查长句、字体回退、遮挡及实际字幕时间。

## 执行器的检查边界

`prepared.verify` 只检查资产完整性，允许读取历史失败包。正常新计划和语言渲染使用 `prepared.verify_for_production`，要求：

- 准备记录的 `approved_for_reuse` 为真；
- `visual_review` 绑定实际审核 JSON 的路径和 SHA256；
- 审核绑定源哈希及实际无字视频哈希，有署名且结论为 `pass`；
- `source_text_removal`、`texture_and_color`、`foreground_motion`、`temporal_boundaries` 均为 `pass`；
- 实际审核证据存在且哈希一致，证据同时列在准备记录的 `inputs`，使交付包可独立恢复。

本地自定义合成脚本也应调用同一制作检查，不得仅调用完整性检查或手工把未审底片标为通过。软件检查只能阻断缺失、失败或错绑的审核，不能证明评语真实，也不能替代实际视觉检查。

## 证据与限制

证据：evidence:gate-verification、evidence:observations。前者验证软件拦截与历史包仍可读取；后者记录单一源的失败机理、用户要求和本次未通过状态。相邻帧恢复虽降低旧色块，但仍产生手腕、指尖、服装边缘错位；没有证据证明它适用于任意运动背景。六个语言是同一底片的六个派生版本，不计作六次独立方法验证。
