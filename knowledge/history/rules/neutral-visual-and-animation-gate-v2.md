# 先证明去字干净，再证明译文贴合

适用：所有视频本地化任务中的必译文字，包括字幕、标题、按钮和拍摄界面。此为用户要求启用的项目检查政策，替代 v1；具体修复算法仍按内容选路。

来源：用户在 2026-10-20 和 2026-10-21 多次指出残字、补丁、译字不贴合及动画简化；本次明确要求将教训用于后续任务。旧规则已经要求检查，但旧自审仍放过缺陷。新增要求是逐实例保存源样式、实际观察和反例检查，不能只签一个总体 pass。

## 1. 制作前写出可比较的呈现要求

每个必译文字实例在原片中确认所属对象、文字与容器边界、字形类别/粗细、实际字面高度、行数/换行、对齐/留白、颜色/描边/阴影、运动/透明度、前后遮挡和进出场。静态项明确写 static；无相应效果写 not_applicable 并说明观察依据。品牌保留项记录理由。

译文先按目标文字系统测量真实字形，再确定排版。长译文优先调整措辞、合理换行及字号，保留容器和可读性；不以非等比压扁字形、超出按钮或统一字体代替匹配。字体无法精确复原时记录近似项，检查形态和视觉重量。口播字幕以共同定稿和实际配音对齐，标题/CTA 以源场景事件对齐。

完成条件：逐实例有源参考、目标呈现要求及已知偏差，后续评审有明确比较对象。

## 2. 先单独看去字结果

逐实例对照同一时刻的原片和实际编码无字底片，暂不显示译文。检查旧字核心、灰色抗锯齿边缘、描边、阴影、光晕和进出场拖影；再查看擦除区域外一圈的纹理、亮度、人物/物体轮廓与运动。背景、前景和目标字层分别处理，译文不能遮盖底片缺陷。

容器轮廓和字形范围分别验证。颜色阈值、OCR、连通域或轮廓检测都只提供候选；相邻手表、图标等对象可能被误并入按钮。遇到区域面积、高度或位置突变，定位相应源帧查对象归属。依据真实表面重建完整污染区，扩大矩形不能替代对象判断。参考须匹配场景、姿态、光照和遮挡；静态供体不能冻结运动头发、手指或物体。

完成条件：每个实例的残字、背景、轮廓/运动、时间边界分别有实际观察。任一 fail 或 pending，底片保持未通过，共享语言制作停止。

## 3. 用实际成片反查贴合与短暂故障

先做一个代表语言的完整编码样片。对照源参考、无字底片、透明译文字层和实际成片，分别检查字形/字面高度、行宽/换行、中心/基线/留白、颜色效果、运动/透明度、遮挡和时序。保留了图形像素还需核对其语义、动画与层级。

- 所有实例查看原尺寸局部和整幅构图，并正常速度检查完整视频；概览拼图只用于定位。
- 所有进出场、切镜、遮挡切换和变形边界查看连续帧，至少包含事件前后各两帧。与邻近事件重合时扩展检查区间。
- 移动/缩放文字、前景交叠、复杂修补及已有用户异议的区域，检查整个相关区间的连续原尺寸帧；记录实际帧号或 PTS，不以固定间隔抽样代替。帧数很多时分段，未看完保留 pending。
- 主动寻找反例：旧字从译字空隙露出；补丁越过圆角或粘上相邻对象；背景译字盖住前景按钮；出场时原字/译字重新闪现；目标字体回退、截字或与原动画不符。

一个语言通过后才扩展批次。每个语言重新核对实际字形、排版、遮挡及字幕同步；共享底片通过不能替代各语言成片检查。纯视觉返工复用声音时核验实际解码音轨及时间映射，已有声音结论的范围保持原样。

## 4. 每个实例留下审查记录

在该候选的哈希绑定评审证据目录保存 `text-visual-audit.json`，由评审人根据真实观察填写，并纳入现有评审的证据清单。记录格式：

- 顶层：源、底片、实际成片 SHA256，locale，reviewer，review_type（同一 Agent/独立），reviewed_at。
- `instances[]`：inventory_id、role、源参考证据、源样式与目标要求、容器/字形区域、实际检查的帧区间或 PTS、检查方法、四层对照证据路径与 SHA256。
- 每实例分别记录 `erasure`、`background_and_foreground`、`typography_fit`、`motion_occlusion_timing` 的 status（pass/fail/pending/not_applicable）、具体 observation 和 evidence；not_applicable 必须有理由。
- 顶层列出未解问题、与源要求的偏差，以及尚未覆盖的区间。必译实例覆盖完整且必需项全部 pass 才能签整体通过；保留项检查保留理由与呈现。

中性底片审查阶段尚无目标成片时，将目标部分保留 pending；中性检查通过后可开始代表语言，成片交付时目标部分必须补齐。模型直接编辑无法提供可分离图层时，记录路线限制，仍需原片/实际输出逐实例对照；不能虚构中性底片验收。

记录应写“在哪些帧看到什么、据此如何判断”，而非重复“已检查、符合要求”。生成图片、运行检测、复制评审模板均不等于看过证据。新编码、新字层或新底片使相关旧审查失效，重新绑定和复核。

## 5. 阻断、修复与软件边界

必译残字、补丁越界、译字截断、错误遮挡、明显动画/时序不符属于失败，整体分数不能抵消。先保存反例，选择可定位的变量有界返工；沿用项目最多两轮返工的限制。证据不足留 pending，不能把用户再次找错当作标准审查步骤。

实际用户异议通过 quality-hold 绑定有缺陷的成片/共享底片哈希；旧评审保留历史，新修复需要新哈希和新审核。总体积极反馈单独保存，不自动扩张为所有细节、母语语音或独立验收。

现有 `prepared.verify_for_production` 核验复用批准、源/底片哈希、署名审核、四项底片检查和绑定证据；`quality` 核验技术指标与评审覆盖。本次新增的逐实例记录是 Agent 必须执行的审查程序，尚无专用解析器自动检查其全部字段，也没有自动视觉识别能证明观察真实。完成报告必须区分程序要求、软件检查与实际视觉判断。

## 证据和可迁移范围

evidence:previous-observations 与 evidence:gate-verification 保留 v1 的失败和历史软件探针；它们不是本次重新运行的测试。evidence:cta-feedback 记录本次用户反例、修正原因与最新积极反馈；evidence:cta-comparison 是实际旧/新成片局部对照；evidence:cta-measurements 是新西语候选的局部检测记录，检测零异常仅覆盖其指定缺陷。

推广的是先验呈现要求、逐实例四层对照、连续帧反查和证据责任。具体坐标、字体、亮度阈值、黑色内区识别及圆形退场拟合均只适用于原素材；同源四语不算四个独立源复验。隐藏纹理、字体及光效可能近似，所有新源仍须重新判断和验证。
