# 视频本地化工作台

网页统一入口为 [译制工作台](http://127.0.0.1:8768/#ledger)。同一导航包含需求台账、效率分析、任务与视频、会话总览、自动任务、知识与调用和运行概况。旧 `/console` 链接转到统一入口，`#requirements` 对应 `#ledger`。会话每页 8 个，节点可查看实际产物、视频和音轨。宿主原生交办由[宿主插件](console-bridge.md)提供。

「需求台账」按本项目统计范围显示制作完成、审核上传完成及素材库投放核对。当前需求版本已核验绑定的批次即时计入审核上传完成。整单核验和结案采用整单回执。复用成片单独显示数量，计入审核上传完成。点击需求编号可展开需求原文、异常说明与核验依据，在「任务与视频」查看各语种的上传状态、复用语种和来源需求。点击负责会话名称可在工作台内打开会话。平台状态采用匹配需求 ID 和编号的较新巡检或需求快照。

同页「制作并发」读取原片名额记录和巡检的待派发清单。现有上限为 10 部原片，同一原片的各语种共用一个名额。预约和建聊待确认均占用名额。排队按派发顺序与剩余名额推算，待准备或核对的原片另列。展开可查看待派发原片和读取时间。

会话列表按最近一次用户提问的时间倒序。助手输出、执行进度、状态同步和自动心跳不改变顺序；没有可读用户消息时以会话创建时间作稳定后备，提问时间显示未记录。排序依据仅从本项目已保存的消息增量读取。

会话详情的“运行时间链路”与“产物流程”独立：按真实阶段/执行开始时间展示节点、起止与秒级历时，区分并行和节点间未记录活动的间隔。Agent阶段历时包含中间过程，不能与脚本计时相加；180秒未获真实活动确认即停止累计。界面同步不登记制作心跳，也不从文件修改时间补造工作时长。“过程知识”及节点弹窗提供工作包知识、冻结计划、报告声明已读、采用反馈与本次经验候选；正文、版本哈希、适用范围和依据可追溯。候选不等于已启用，声明阅读不等于采用或效果验证。

会话与自动任务视图通过本机文件事件更新，页面隐藏时断开。交办和桌面状态同步由用户点击触发。网页提供单次交办指令，宿主插件按其实际能力直接通知。

工作台使用项目已有 Python 和标准库。打开台账或点击刷新时读取数据。后台采集线程每 15 秒核对本地记录。台账核心在 `src/video_localizer/ledger.py`。

默认台账列出状态、去重语种数、制作完成数、审核上传完成数、负责会话和实际起止时间。缺整单制作完成时间时，可显示已记录的结案或平台核验时间，并标注其类型。淡绿、淡黄和淡红底色仅用于状态列，竖线分隔各列。Fireplay 平台显示已完成时，需求状态显示已完成。审核上传完成数和会话用量继续以当前版本的核验回执为依据。异常说明和任务与视频可按需展开。效率页每条已完成需求显示总耗时、语种数和每种语言平均耗时。平均耗时按总耗时除以需求去重语种数计算。页面顶部显示需求总耗时的截尾平均数、中位数及样本量。截尾平均按有效样本排序，去掉两端各 10%（向下取整），不足 10 条时使用全部样本。耗时异常可在「记录说明」查看。统计范围见 [Benchmark](../docs/benchmark.md)，管理操作见 [需求台账](../docs/ledger-phase1.md)。

效率页底部从 `workbench/legacy-benchmark.json` 显示原项目清理前的固定统计快照。历史耗时和 Credits 按需求统计，Token 按会话统计，平均值未截尾。各阶段耗时为单次调用或回执计时。快照独立于当前查询和本地运行目录的清理。

新旧项目使用各自工作目录里的 `state/ledger/ledger.sqlite3`。优化后的工作台使用 8768；在优化前项目目录运行 `sh workbench/start.sh --background --console-only --port 8769` 可查看旧项目的本地快照。`--console-only` 不启用定时采集。

## 启动

macOS/Linux：

```sh
sh workbench/start.sh --background
# 指定已通过 doctor 的 Python
WORKBENCH_PYTHON=/实际路径/python3 sh workbench/start.sh --background
```

通用启动为 `python workbench/start.py --background`。后台PID和日志在work/workbench；不安装系统开机项，不自动停止占用端口的进程。

在项目根目录运行：

```powershell
workbench/start.ps1
# 独立后台启动并打开浏览器（关闭启动终端后仍运行）
workbench/start.ps1 -Background -Open
# 自定义端口
workbench/start.ps1 -Port 8769
```

打开 <http://127.0.0.1:8768>。服务默认只监听本机，前台模式在终端按 Ctrl+C 停止。后台模式的进程号和日志写入 `work/workbench/`。端口占用时选择其他端口，不会自动杀进程。

需要在可信局域网查看时，使用 `sh workbench/start.sh --background --lan-network 192.168.1.10/24`，将地址及前缀替换为本机实际 IPv4 和子网。该子网内的设备可直接访问 `http://192.168.1.10:8768/`，无需登录。局域网端只读，本机管理入口为 `http://127.0.0.1:8768`。HTTP 连接未加密，限可信局域网使用。IP 地址变化时按实际地址重新启动。

公司网络已开通跨网段访问时，可用 `--lan-allow 192.168.12.0/24` 允许该网段通过同一个工作台地址免登录查看。多个网段分别追加一个 `--lan-allow`。

也可以直接运行：

```powershell
.venv/Scripts/python.exe -B workbench/server.py --port 8768
```

## 当前版本

- 台账：关联已登记Fireplay需求、预算、批次、run及经哈希核验的独立交付包；无法可靠关联的记录单列，不计需求完成量。
- 效率：按已完成需求展示总耗时和每种语言平均耗时。
- 跟踪：原视频认领租约、实际阶段、心跳及等待原因，脚本执行器心跳与 Agent 活动分别登记。

- 任务：读取 `runs` 与`state/delivery-index.json`（不存在时兼容 `outputs/index.json`），现场清理后仍显示独立交付包。按源视频分组，支持语言/名称搜索及状态筛选。
- 视频：原片与当前结果并排、单路选听、同步定位、按实例跳转、前后帧近似寻址、独立版本播放。需要精确判断时仍使用实际导出帧与 PTS。
- 内容：文字/口播实例、译文、处理理由、已有问题观察、质量失败、成片瑕疵。
- 知识：现行方法、同源参考、候选索引；任务的冻结知识、Codex 工作包、声明阅读和真实 `knowledge-use` 回执分别展示。未记录不推断为采用或有效。
- 执行：最近模型回执、Codex 观察/产物、阶段耗时、维护暂缓和持久后续待办。
- 运行概况：完成需求的关联会话在首次读取时保存 Codex Token 和可归属的 KIE 实扣。顶部显示有 Token 记录的会话截尾平均用量及实际总量，并列出已完整确认实扣的会话截尾平均 KIE 花费（Credits）。两项分别对有效值去掉两端各 10%（向下取整），显示实际覆盖数和平均样本数。有记录的零用量或零实扣属于有效样本。Token 明细从与快照总量及时间对应的本地会话日志读取，展示输入、输出和缓存命中。缓存命中计入输入。
- 需求台账按需求创建时间从新到旧排列。末列显示每条需求的 Codex、KIE、Fireplay 回传重试及中断，点击后在该需求下展开明细，每页 30 条。Codex 数字包含宿主重试、上传完成前实际发出的督促和有回执的会话接替。宿主日志首次补录最近 7 天，督促和接替按已有项目回执补录。KIE 依据脚本记录及任务绑定。Fireplay 读取已登记的文件重传及素材绑定重试。素材绑定回执的 `dispatch` 保存重试派发时间、实际参数、原操作和原失败回执的 SHA-256，回传结果依据该需求的素材读回更新。可确认的关联和事件保存在 `state/retry-activity/events.sqlite3`。

制作记录仍只读。新增的受控本机POST只登记台账认领、阶段、等待、ETA和关联事件，检查同源、防跨站令牌、幂等ID与记录版本。没有制作、重试、质量审批、清理或对外提交按钮，不把命令字符串发送给shell。

## 与当前框架的关系

制作规则集中在 `agent/contracts` 和 `agent/workflows`，执行仍由 `src`/`bin` 承担。Codex 主导视觉、翻译及判断；专用模型处理真实音视频。安装资产属于 `.runtime`，`work` 只承担临时内容；`runs` 是现场，`outputs` 是独立交付，`state` 是跨任务状态。工作台不搬迁这些数据。

新版默认快速交付，达到边界后 `finalize` 输出最佳完整译片。因此输出状态与质量状态分开，`delivered_with_issues` 不显示成质量通过；历史质量异议优先提醒。`state/deferred-delivery` 是持久待办，不代表后台已运行。`maintain --close` 可能退休 run，工作台从独立交付包继续查看。

工作台通过直接读取规范文件展示制作和用量，失败与重试索引从已有记录独立更新。页面阶段是基于记录的导航摘要。执行时以项目原门禁为准。

## 真实性与读取边界

- 打开页面或点击标题旁的刷新按钮读取已落盘状态。Fireplay只读取现有宿主流程登记的快照，页面展示快照时间。进程是否存活需另行核对。
- 计划/回执/版本保留原绑定。交付索引与 manifest、视频哈希核对后才显示正常；哈希缓存只用于查看性能，不替代交付门禁或完整包审计。
- 质量标签是记录的结论，不证明实际视听、独立审核或用户验收。全流程仍需要实际观察。
- 仅提供范围内媒体和知识文本；除固定交付目录 `outputs/.packages/` 外拒绝隐藏路径、父路径、工作区外链接、任意静态目录与非台账写入。隐藏常见凭据字段、Bearer值及远端签名地址，不开放state数据库文件下载。
- 浏览器关闭不改变任务。未接入项目规范记录的临时脚本可能无法显示完整过程。
- 历史包不一定保留所有源帧和任务文件；缺失内容显示“未记录”，不会自动重建或调用模型。

## 后续真实需求 Benchmark

“效率”页增加前瞻基准，不重做历史需求。首轮完整输出、后续返工、明确等待、执行器占用和未分类间隔分别统计，按时长/复杂特征/原片与语言数量/代码版本分组。启用基线与首轮质量快照保存在台账中，交付包到期不删除样本。新需求自动采集，Agent负责真实活动与阻塞上报；详见[使用与统计口径](../docs/benchmark.md)。
