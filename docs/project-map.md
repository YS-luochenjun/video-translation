# 项目维护地图

从 [AGENTS.md](../AGENTS.md) 进入制作，从 [制作合同](../agent/contracts/workflow.md) 查现行步骤。目录不用整体搬迁；源视频、交付包、知识和账本各有独立引用，按文件名整理会破坏恢复关系。

| 要解决的问题 | 唯一入口 | 留存位置 |
| --- | --- | --- |
| 模型、预算、审核和最终输出要求 | `agent/contracts/` 与对应 `config/` | 合同描述含义，配置提供参数；旧账本保留原限额 |
| 视频如何制作与接需求 | `agent/workflows/` | Fireplay 入口见 [需求承接](../agent/workflows/fireplay-intake.md) |
| 方法为何适用、有什么反例 | [知识索引](../knowledge/README.md) | `rules/` 正文、`examples/` 独立证据、`cases/` 精确同源观察 |
| 哪些经验尚未处理 | `knowledge-queue` | 候选原文不变，审查链提供当前状态 |
| 动态标题、CTA、关键词 | [Remotion 接入](remotion-typography.md) | 显式动态实例走 Remotion，简单文字走 FFmpeg，失败回退仍需审核 |
| 字体、文字容器和局部修复 | [字体](fonts.md)、[容器与运动修复](container-motion-repair.md) | `src/`、`bin/` 是可复用能力，实例参数留任务中 |
| 实际输出、费用未知和外部提交进度 | 当前 run、独立交付 manifest、`state/` 回执 | 报告和聊天只是来源，不能替代实际哈希及任务回执 |
| 临时缓存与收尾 | [存储合同](../agent/contracts/storage.md) | `work/` 可重建，`state/` 恢复状态不随缓存删除 |

## 看当前知识状态

使用 doctor 确认过的 Python 运行：

```sh
python3 bin/project_health.py
```

生成 `work/project-health/knowledge.json` 和同名 Markdown，列出当前方法、同源案例、候选家族和成员来源。家族只是浏览分组，同源多语/多轮版本不合并验收或放大证据强度。这个命令不调用模型、不整理媒体、不写外部平台。

占位复盘如 `Needs an evidence-backed lesson` 保留在审查队列，但不占制作建议的召回名额。新复盘会给出待补经验状态和真实质量摘要；摘要不是可直接采纳的方法。派生候选索引的 `current_review` 指向当前审查，原始 outcome 保留历史含义。

`bin/close_empty_reflections.py` 仅用于已经逐源检查的旧自动占位记录：先传明确源哈希生成预览，再用同一指纹、审查人和来源执行。它走既有审查/归档机制，归档公共原文并关闭私有占位待办，保留案例、历史质量、媒体和账本。自定义文字、真实限制、已有审查或新证据摘要不在批量处理范围内，不能拿它清空整个队列。

## 实测经验从哪里进入项目

2026-10-27 的七组实测整理见 [来源对应表](../knowledge/curation/seven-source-review-20261027.json)。共七个独立原片、70个源语言组合；70份报告所列输出已核对实际字节哈希。这是结构/证据检查，不是重新完成70次视听验收。

视觉反馈合并进现有 [文字与前景方法](../knowledge/rules/method-animated-text-occlusion-v8.md)，同源观察进入 `knowledge/cases/`；既有声音核对、容器排版和语义强调方法继续使用，不按每种语言复制规则。旧版方法、失败判断和未知费用仍保留。五个聊天因读取服务大小限制无法完整取得，明确使用本地绑定报告/反馈补足，未声称完整读到聊天。

后续候选的逐条审查回执见 [审查记录目录](../knowledge/curation/reviews/)。已核验的历史使用回执、已采纳方法和无结论占位分别登记审查；转动纸面、UI供体、漏识别CTA等以精确同源观察保存。字体选用与取帧检查合并进现有视觉方法，路线方法修正过时政策引用。方法数量不因历史语种数增长。

“保全了运行观察、等待提纯”也不是制作建议。新的使用回执保留逐方法结果，但同一句观察在摘要中只显示一次；旧回执原文和哈希不变。部分采纳记录仍有明确补证任务，不因其余内容已合并而归档整条候选。

最后一条隐藏RGB假设已通过实际资产和下游读取/变换验证，按有条件的透明资产导出检查合并，原候选完成审查并归档。详见 [兼容性验证](alpha-asset-compatibility.md)；普通逐通道缩放与低alpha阈值是已记录反例，不采用无条件清理。本轮整理是否有新增待办以 `project_health.py` 的当前结果为准。

日常维护先处理本次新增反馈及其同源版本，给出具体动作、适用条件、失败签名和停止条件。候选到正式方法必须有带来源的审查；目录变整齐或素材上传完成，都不构成质量通过。
