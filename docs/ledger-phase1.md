# 需求台账与效率工作台：第一期

2026-10-27 用户授权在现有工作台实现，并关联既有需求及任务。沿用 Python 标准库、原生 HTML/CSS/JavaScript；无新增云服务、付费模型、平台写入或前端构建依赖。

## 启动与持续采集

macOS/Linux：`sh workbench/start.sh --background`；可用 `WORKBENCH_PYTHON` 指向 doctor 核验的 Python 3.10+。Windows 沿用 `workbench/start.ps1 -Background`。通用入口：`python workbench/start.py --background --port 8768`。端口占用时报告错误，不杀已有进程。日志和PID回执在 `work/workbench/`。

访问 `http://127.0.0.1:8768/#ledger`。服务运行时每15秒核对本地记录；页面每5秒读取。浏览器关闭不影响采集；电脑休眠、重启或服务退出时停止，重新运行启动命令可恢复。本期不安装系统开机服务，也不将本地采集器冒充可调用Codex推理的后台Agent。

Fireplay范围为已由现有接入流程登记到 `state/fireplay` 的需求快照，页面展示最新快照时间。采集器不持有平台登录，不自行调用宿主连接器；新的平台快照由既有Fireplay宿主接入流程写入后进入台账。它不代表平台全队列实时同步。聊天清单只保存本项目真实读取快照，聊天状态不当作执行心跳。

## 粒度与来源

- 需求 → 原视频 → 语言任务；多个执行run和视频版本归到同一语言任务，不增加需求数。
- Fireplay平台ID、已登记预算/批次成员与源哈希优先。历史完整编号还须与预算授权引用交叉核对；仅文件名类似不足以合并。
- 既有用户确认的 `state/delivery-folders.json` 源哈希映射，加上已核验交付manifest，可以关联没有旧批次指针的修复成片。未交付实验不会仅按相同源哈希混入正式任务。
- 证据不足的记录留在“待关联”，不计需求产出；人工关联校验源哈希和目标语言，保存原因。
- 需求范围保存不可变版本；收件登记、平台创建、首次发现、信息齐备、首次完整输出和当前输出分别记录。缺失时间不使用文件修改时间补造收件事实。
- 交付包清单和视频哈希匹配后才计输出；候选不计。必需配音的字幕候选不计满足请求。带瑕疵输出、质量通过、质量异议、平台提交和用户验收各自保留。只出现历史记录不代表正在执行。

## 页面与操作

“需求台账”展示数量、语言进度、负责聊天、首次和最新ETA、实际完整输出、阻塞及阶段。可按编号/标题、状态、语言、负责聊天/执行者筛选。默认正式需求列表与待关联记录分开。详情提供语言矩阵、成片、执行run入口、范围、ETA历史及最近160条事件。

“效率分析”提供7/14/30/90天登记与首次完成趋势、交付周期中位数、预测偏差及覆盖率。周期使用America/Los_Angeles自然日；其余页面明确显示时区。

受控本机操作：认领、阶段、真实心跳、释放、信息齐备、等待、恢复、ETA及任务关联。所有操作留事件，检查稳定操作ID；UI还检查记录版本。认领按原视频设置租约，同需求的不同原片可并行；整体认领不能与原片认领重叠。过期接管需说明恢复依据，不自动重做模型任务。

写接口只作用于台账，不签署质量、不启动制作、不改变预算、不写Fireplay、不清理素材。需要本机Host、同源Origin、会话防跨站令牌和JSON请求；未知方法/动作不能成为shell入口。

## ETA与效率口径

初始规则在 `config/ledger.json`，明确为**未校准的规则估算**：排队余量＋各未完成语言任务余量＋需要继续处理的共用源片余量。它不是供应商时长承诺，也不推断真实Agent排队顺序。为整条需求及各原视频分别建立预测。只在有新阶段证据时追加滚动预测，不因刷新或超时自动顺延；Agent/人工预测不会被规则覆盖。

历史已完成任务不补造首次ETA。范围改变后新建该范围的估计，旧估计仍可查询。事后登记预测标记retrospective，不计准时率。人工估计保存依据、未确认因素和时间上下限，不提供伪造的统计置信度。

- 完成量：所选期间首次完整输出的去重需求数；返工不重复计数。
- 交付周期：收件登记至首次完整输出；另列信息齐备至输出。只使用时间齐备且顺序合理的样本。
- 准时率：筛选需求中，当前范围首次预计上限已经到期的需求里按时完整输出的比例；已逾期未完成者纳入分母。它使用全部已到期预测，页面单独标注，与趋势周期区别。
- ETA偏差：期间完整输出时刻减对应首次预计上限；正数表示超出上限。
- 缺失时间、ETA和反馈不当零或通过。阶段含嵌套，不相加为Agent工作时间；本期不根据空白时间推算工作/等待占比。

## 执行接入与恢复

`work-packet` 返回 `ledger_tracking`。实际Agent上报见 [台账工作流](../agent/workflows/ledger-tracking.md)。现有脚本顶层计时阶段自动写开始/结束，并在长阶段每60秒写执行器心跳。执行器、采集器和Agent三种活动分开。读取页面或扫描目录不会替Agent发心跳。

SQLite数据库位于 `state/ledger/ledger.sqlite3`，启用事务、WAL和完整同步。管理事件和ETA追加；制作规范文件仍是质量、费用、模型和外部回执的依据。脚本事件先进入持久inbox，数据库暂不可用时后续补登，不重新执行制作。输入损坏时保留上次有效登记快照并标记部分同步。重启后恢复检查点和租约，未知模型/外部写入继续按原流程核查。

命令入口（用已验证的Python运行 `bin/va.py`）：

```sh
python bin/va.py ledger preview
python bin/va.py ledger sync
python bin/va.py ledger status
python bin/va.py ledger detail --id '实际台账ID'
python bin/va.py ledger backup
python bin/va.py ledger claim --spec work/实际台账规格.json
```

`preview` 不登记需求/事件或触发制作；首次使用会初始化空台账schema。迁移回执放work，持久数据库放state。`register` 支持非Fireplay的明确请求；规格见台账工作流。台账不分配新付费额度。

`ledger backup` 使用SQLite在线一致性备份并检查完整性，保存在 `state/ledger/backups/`。恢复时先停止台账服务，保全现有数据库及其WAL/SHM，再从完整性核验通过的备份恢复；保留必要的源状态、预算、交付库和质量异议，启动后重新对账。单独台账不能恢复已删视频。
