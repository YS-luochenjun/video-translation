# 缓存与执行恢复

## 生成前复用与审核边界

新生成的 comparisons-v3 检查材料会先按实际素材哈希、解码器和处理代码版本、裁剪区域、实际帧号及图层标签查询缓存。未变化的图层直接从已校验的无损比较图中取回，不再启动对应的视频裁剪解码。原片时间戳和媒体信息也按内容与工具版本复用；变化的目标视频仍需取得实际时间戳并解码，不能仅凭“只改了四帧”的说明跳过新画面。

当一页所需的全部图层、帧号、区域和排列均与既有完整图片一致时，直接校验并复用整页，不再解压图片、拆分图层和重新拼图。只有部分图层相同时才走图层级复用。单纯避免视频解码不保证提速，实际素材的第一次图层缓存试验曾因 PNG 开销变慢，测试记录保留用于比较，不能把缓存命中率当作性能结论。

新目标视频的实际图层仍逐帧解码并计算包含尺寸的像素指纹；若它与旧页中对应图层像素完全一致，且其他所需图层也一致，可以直接复用旧页的图片字节，不再读取并拼接未变的源图层。任何一层像素不同才重新拼图。新页的素材哈希、实际帧号、PTS 和审核绑定仍来自新版本，像素相同不意味着复制旧通过结论。

部分图层复用使用单次操作内最多 32 MiB 的 RGB 图层内存缓存，重复字节不反复解压，达到上限即淘汰旧条目，不额外写图片。读取缓存图片前仍核对文件哈希；同一操作内已经证明相同的“像素指纹 + PNG 文件哈希”不重复解压校验，下一次操作重新核验，不用长期 mtime 信任代替内容校验。

缓存只增加 `state/visual-decode-cache/` 下的时间戳和图层定位 JSON，不另存全量帧或视频。新证据仍有自己的完整图片路径、全部原定帧、实际时间映射和 pending 审核模板。透明图层缓存的是原有灰底合成后的展示图层，保留原来的 alpha 呈现，不把透明图误当成不透明源素材。旧版本的观察、失败图片与审核状态均不修改。

文件不存在属于可重建缓存缺失，只解码缺少的帧；文件或索引校验失败则停止并保留现场。跨任务共享索引采用锁和原子合并；取证完成前再次核对输入没有改变。新证据不依赖旧目录才能打开，删掉旧目录也不能带走新证据的图片。

`visual-evidence` 返回并在新 manifest 中记录 `decode_reuse`：复用/新解码的图层帧数和时间戳缓存命中数。图层帧数是请求输出的唯一帧数，不等于编解码器内部实际扫描帧数。`pixel_storage` 区分硬链接、复制和新写入，并记录复制回退的错误编号；不能将缓存命中数直接当作磁盘节省量。

诊断时可运行 `visual-evidence RUN --no-decode-cache`，对尚未生成的证据绑定禁用时间戳和图层解码缓存；已有完整不可变证据仍校验后复用，不覆盖旧审查。图片像素去重仍保留，参数不跳过任何质量门禁。旧证据不会为了升级而重写，首次遇到新的解码条件需要建立定位索引，后续才受益。

渲染检查点和片段缓存改为跟随明确的渲染模块集合及 Pillow 版本，不再因存储清理、报告或证据查看模块的独立变化而重新编码。源片、文字、时轴、绑定资产、字体及编码器变化仍参与原有失效判断。新增渲染依赖时必须更新 `render_cache.implementation_signature` 并补测试；该优化不放宽准备资产、质量异议或最终成片审核。

当前未实现自动清理、跨 run 的通用渲染片段共享或任意修复脚本的局部增量执行。历史专用脚本仍可能整段重做；新图层缓存不意味着新目标视频可以免解码或免审查。

使用、边界及中断处理见 [修复配方](../agent/workflows/repair-recipes.md)。本轮没有自动水印语义分割或跨源参数迁移，也没有完成 de2us 的音频听感验收。旧的素材专用脚本仍作为历史记录；新通用入口不意味着所有旧脚本都受试验预算控制。

## 常用入口

从项目根目录执行，`RUN` 替换为实际任务 ID，路径均相对该 run：

```powershell
bin/va.ps1 resources
bin/va.ps1 work-packet RUN
bin/va.ps1 work-packet RUN --stage translation
bin/va.ps1 asr RUN --audio analysis/source.wav
bin/va.ps1 asr RUN --audio analysis/source.wav --model small --download
bin/va.ps1 tts-packet RUN --voice Kore --estimate 2
bin/va.ps1 audio-mix RUN
bin/va.ps1 production RUN
```

先确认 `analyze` 返回的实际音轨路径，不假设所有旧 run 都叫 `analysis/source.wav`。ASR 不传 `--audio` 时读取 capture 已提取的当前成片音轨；`--language` 是识别提示，不是已检测到该语言的证据。`--download` 只在当前 small 模型缺失时下载，完整模型不会再次下载；底层下载器也拒绝旧型号。历史模型只能只读核验，不提供重新下载或安装。转写结果仍是待核对证据。

`tts-packet` 不付费；检查包后才走原 `model-task --execute`。未知远端状态先核对 taskId 和账本，不能新建包绕过恢复。`audio-mix` 读取已有的 `inputs/narration-plan.json`：源哈希、背景路径/哈希，以及 lines 的实例 ID、定稿、起止时间、声音路径/哈希；可选声音增益与偏移仍使用原字段。CLI 返回新音轨的实际路径，应绑定进 inventory 并按 `agent/contracts/captions.md` 对齐实际声音，不能沿用旧的固定输出路径。

兼容脚本 `bin/asr.py`、`bin/mix_localized_narration.py` 保留，调用同一执行器；`bin/separate_local_audio.py` 继续负责 UVR。需要 Python 时使用项目运行时，而不是临时重新安装依赖。

## 检查点与恢复

| 内容 | 位置（相对 run，另有标注除外） | 恢复原则 |
| --- | --- | --- |
| ASR 历史结果 | `analysis/asr/<指纹>.json`，音频旁兼容别名 `offline-asr-*.json` | 输入相同复用；修改音频/模型/提示后重新识别；别名不是历史唯一副本 |
| 已解码源立体声 | `outputs/source-audio/<指纹>/` | 绑定源片和解码器；不同于 analyze 的源观察音轨 |
| UVR 输出 | `outputs/local-separation/<指纹>/`（默认） | 验证音轨、模型、实现、输出哈希后复用 |
| 版本化混音 | `outputs/audio-mix/<指纹>/` | 包含对齐音轨、配方和最终 WAV；变更生成新版本，不覆盖旧版本 |
| 视觉片段缓存索引 | `outputs/render-cache/` | 引用已存在的静音片段，不再复制一份视频；缺片段重建，哈希异常停止 |
| 整片检查点 | `outputs/production-checkpoint.json` | 全部输入一致才跳过编码；仍取证和 quality；`--force-render` 同时跳过片段缓存 |
| 资源锁 | 项目 `state/resources/` | 忙时停止并重试原命令；崩溃留下锁，查 PID、进程及账本后才处理，不抢占活锁 |
| 下载锁/回执 | 项目 `.runtime/models/asr/<模型>/` | 下载异常不写成功回执；完整性失败先查明，不把坏文件当作模型 |
| 任务及费用 | 原 `runs/<ID>/jobs`、`state/budgets`、`state/batches` | 沿用原恢复与核账，不删除或重置 |

新增本地资源配置可选：`config/resources.local.json`，仅含 `max_heavy_jobs`（1–8，默认 1）和 `minimum_free_mib`（至少 64，默认 256）。这是重任务启动硬底线；原 storage-policy 的空间告警是另一项检查。下载和归档增加已知数据量，任意长片渲染体积尚不能准确预估，不能保证中途永不耗尽空间。资源限制只覆盖接入的项目入口，不拦截历史临时脚本或其他工作区的进程。

片段缓存按现有计划分段；没有自动将整片计划重切为逐帧任务。系统字体使用已列出的常用字体和项目字体哈希；自定义系统字体、字体回退或外部渲染环境改变后须 `production RUN --force-render`。2026-10-22起整片检查点核对计划和显式媒体/工作区绑定依赖，未绑定的诊断文件不影响渲染；质量审核仍核验实际证据。

## 质量与知识边界

缓存是“这些字节之前生成过”的凭据，不是“这些字节合格”的签字。底片、代表语言、逐实例视觉、原音乐、字幕同步、翻译和质量异议仍走原门禁。复用只跳过确定输入对应的机械工作，不填写 `pass`，不自动放行批次，不代替真实听音。

work-packet 的六阶段是导航，任务可以回退或交错；它不能自动判定当前已完成哪个创作步骤。正式知识仍按现有检索条件返回，并单列同源参考，不能保证任意问题自动命中正确方法。AI 仍需阅读方法、辨别适用性和反例。

deliver 继续自动生成机械事实、归档和候选入口；AI 只需补有价值的观察、原因、修改变量、适用条件和剩余问题。候选不自动成为全局规则。执行优化不等于训练模型或证明新视频质量。

## 收益与验证

应减少重复脚本、相同音频的再次识别/分离/混音、完整模型的再次下载、未变片段的重复编码，以及重复手填路径/状态/哈希。首次复杂背景修复、译文润色和实际视听检查仍可能耗时；没有真实同素材对照，不能承诺“一小时降到多少分钟”。

执行回归位于 `tests/test_workflow_optimization.py` 和相关缓存测试；历史边界见 [维护摘要](history.md)。后续用 `timing RUN` 比较同等质量门禁下的首次运行、检查点恢复和局部修改，区分本地计算、供应商调用和未观测间隔；不把间隔统称 Codex 写文件时间。
