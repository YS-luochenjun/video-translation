# 项目方法论与知识闭环

本项目已形成可执行的方法论：先观察信息载体，按条件选择方法，以实际产物验证，在预算与返工边界内输出，再把有来源的经验送回下一次制作。Codex负责语义和质量判断，执行器负责媒体、模型任务、费用、状态与证据绑定。现行规则仍以[制作合同](../agent/contracts/workflow.md)、[知识合同](../agent/contracts/knowledge.md)和配置为准；本文解释整体关系。

## 从需求到交付

| 环节 | 核心判断 | 可复查结果 |
| --- | --- | --- |
| 承接与恢复 | 当前需求、所有原片/语种、已有聊天和账本是什么 | 请求版本、源哈希、授权、独立请求预算；unknown先核对 |
| 真实观察 | 信息主要靠人声、画面文案还是两者共同传递 | 按实例记录旁白/对白、文字区域与时间、运动/遮挡和疑点 |
| 按内容选路 | 哪个方法适用，何时换路或停止 | content_features与routing_assessment；首选、备选和实际理由 |
| 检索并冻结 | 政策、条件方法、同源案例分别支持什么 | context与plan冻结正文哈希；候选仅作风险提醒 |
| 制作与核验 | 译稿、声音、字层和底片能否共同成立 | 实际render/capture/review/quality，证据绑定成片哈希 |
| 有界收口 | 能否继续改善，是否达到预算或两轮返工边界 | 当前最佳完整译片；质量通过、带瑕疵输出及用户验收分别记录 |
| 提交与学习 | 平台实际受理了什么，下一次可复用什么 | 独立交付包、平台读回/绑定、候选/使用反馈和维护回执 |

默认[快速交付](../agent/workflows/fast-delivery.md)，必要时选严格路线。快速路线保留基本完整性和证据门禁。真实必需配音缺失必须明确报告。共享底片可以在核验后跨语言复用，新语言的定稿、配音、时轴、字层与成片审核各自建立。

选路依据见[三类信息载体](../knowledge/rules/content-led-localization-v1.md)和[方法选择](../knowledge/rules/agent-method-selection-v2.md)。简单底面、运动复杂底面、前景遮挡分别判断；固定模型不等于固定效果。模型API成功、技术检查通过、Agent自审、独立审核和用户验收各有自己的证据。

## 哪些经验才算被吸收

知识有三个出口：通用/条件方法进入rules及正式索引；源限定观察进入cases及同源索引；证据不足或假设仍保留candidate。失败、反例和“这次未使用”同样有价值，但不能伪装成算法成功。必要对照独立打包，不依赖可删除的任务目录。

`deliver/reflect`自动记录来源，Hook提炼触发条件、动作、失败签名、限制与下一次反证，`knowledge-review`决定合并、限定参考、待补证或历史保留。需要新方法或修订时先`knowledge-promote`，再绑定实际目标版本。完全处理后才能指纹归档原候选；部分采纳仍保留待办。制作通过`knowledge-use`反馈实际效果，反例返回修订队列。

“有候选文件”“已提纯”“正式检索可用”“实际使用有效”是四种状态。相同内容且scope一致才合并；同源十种语言或多轮返工仍然只有一个独立来源。旧失败、费用未知与原验收不被新总结覆盖。

## 自动沉淀如何运转

当前有即时记录与独立定时整理两层触发：交付/复盘自动记录，每次制作、修复、反馈结束由Agent处理本次经验；独立经验任务每天洛杉矶时间18:00处理全局待审，到期运行`hooks run --due`。Fireplay每30分钟只做发现和接入调度，独立存储任务每天18:30整理已结案内容。见[三项定时职责](scheduled-tasks.md)、[每日提纯](daily-knowledge-curation.md)和[知识技能](../.agents/skills/knowledge-curation/SKILL.md)。

本次补强收尾和独立经验任务的主动检查，并让`hooks status`同时显示`adoption_queue_open/review_required/review_next_action`。仅`new_records=0`不能说明全部吸收：它可能只表示来源已经送过提纯，候选仍待审。现在经验任务可以直接识别并处理这层差别。

本机应用调度按用户最新要求分为巡检、经验、存储三项，不要求始终打开三个聊天；具体制作继续由原负责聊天执行。仓库配置不等于独立后台服务安装完成，调度成功也不等于知识采纳成功。当前macOS没有本项目独立系统定时器的安装证据，持续唤醒依赖应用；Windows可按文档选择项目触发器，避免重复调度。电脑、宿主、权限或文本推理不可用时应保存缺口，而不是声称已整理。

在既有授权下，Agent可以自主完成有证据的整理、审查、发布和归档，不需要用户逐次提醒。证据不足时保留具体补证动作；公司偏好/质量标准变化仍需要对应明确确认。自动化的目标是稳定推进这个闭环，不是自动把所有候选变成规则。

## 本轮续整理与完成边界

本轮将发布者水印/片尾同标去除、执行人设计师及二创归属写入现行入口，并同步四个实际活跃的制作聊天。MOG010已经五语交付，没有重新唤醒制作。规则送达、聊天理解、实际制作采用、平台读回通过分别记录；新规则不构成重复上传或预算扩容授权。

本轮续整理后的时点为25条方法/政策、32条同源参考、196份归档候选，登记待审0、空白占位0、Hook新输入0。7份已结清候选按精确哈希归档；MOG010的日语静态供体与CTA时间分歧保留为一个同源案例，其他四语不增加独立视觉来源数。新增规则仍以原文及证据哈希检索，原失败、前次pending审查及未知费用继续可追溯。

“队列处理完”说明当前已登记来源都有明确出口，不说明所有经验已验证完美：ImageGen参考图不保证连续视频通过，静态供体不能推广到移动表面，模型时间标签不等于测量值，独立/母语验收仍有范围。当前四条制作继续产生新观察；历史聊天读取有大小限制，临时目录还包含报告副本、证据和旧队列快照，不能用文件数当作未吸收经验数，也不能声称已穷尽每份历史内容。

继续依靠结案记录、独立经验任务与实际使用反馈增量推进。必要当前证据不足时保持pending；证据已足以支持限定案例时先落地案例，把跨源验证作为未来扩大范围的条件。知识归档不撤销费用、质量或平台恢复中的未解事项。
