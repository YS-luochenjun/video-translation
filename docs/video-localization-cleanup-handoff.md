# 视频翻译项目清理复盘与图片翻译迁移指南

本轮优化清理了旧项目的退役数据，提纯了现有知识，并改进了经验积累、制作产物复用与回收以及 Fireplay 下载和回传。项目以持续承接需求和交付为目标，长期保存会帮助下次制作的方法、案例和必要记录。图片翻译可以沿用同样的治理方式，再按自身的文件、审核和平台规则设定保留期限。

## 视频项目做了什么

| 事项 | 已落地的做法 |
| --- | --- |
| 优化版独立运行 | 建立独立 Git 对象库，保留原远端，迁移运行时并在优化版目录验证。旧版处理前核对在制依赖和真实交付，将历史数据按用途分批清理。 |
| 清理现有知识 | 区分现行方法与政策、精确同源案例、待审经验、历史和操作流水。同义且适用范围一致的经验归并。与现行规则冲突的候选暂停建议，交人工查证。已审结、被完整覆盖且无现行依赖的旧内容可以清理。 |
| 管理新增经验 | 普通任务结案记录质检、交付和费用。有证据支持且会改变后续决策的新原因、修法、反例或成本改善才形成候选。全局经验总结由用户在工作台手动触发，审定后发布，定时总结已关闭。 |
| 降低制作开销 | 同源素材的解析、源图层和已校验底片按实际输入和版本复用。取证用按时间或镜头组织的对照页，保留关键区域原尺寸证据。缓存命中时跳过对应的重复解码或编码，目标语实际成片仍单独审核。 |
| 限制本地产物 | 默认轻量交付包，含最新版成片和必要审核记录，本地保留最多 14 天。有效结案后的制作现场通常缓冲 2 小时。无主已登记缓存为 24 小时，闲置且无引用的源缓存为 7 天。按回执、依赖和本机授权执行清理。 |
| 精简 Fireplay 回传 | 用 MCP 填好名称、英文标签、组共享、设计师和创作类型，核验入库并绑定需求。支持预签名后并行传输、批量入库和批量归属。实际上传容量由平台决定，项目保留操作去重和回执。YouTube 默认请求自动上传，账号、额度、排队和发布进度由 Fireplay 接手。 |
| 原片下载可恢复 | 精确查询后先登记素材 ID、资源 ID 和地址。传输中断后沿原资源恢复，已经校验过的本地原片按哈希复用。遇到单项已发起但结果未知时，先核对该项，其他就绪素材继续推进。 |

视频项目中，`knowledge/` 内可审阅的项目知识随 Git 管理。客户原始资料、私有证据、运行目录、交付媒体、平台回传和费用账本各按用途保留。知识正文及必要案例可独立于已清理的制作目录使用。规则和期限以项目合同为准。[知识合同](../agent/contracts/knowledge.md) · [存储合同](../agent/contracts/storage.md) · [Fireplay 接入与回传](../agent/workflows/fireplay-intake.md) · [手动经验总结](daily-knowledge-curation.md)

## 图片翻译项目怎么迁移

建议按三个阶段实施，每一阶段先用少量新需求验证。

### 第一阶段　盘点依赖和清理旧产物

1. 确认现用工作区、代码分支、配置、模型运行时、任务台账、知识和交付目录。优先验证当前版本能独立接入一个新需求，再验证一项已有任务能从原记录继续。
2. 按用途列出大目录的占用和保留理由。优先处理已确认结案、无在制引用的旧中间图、冗余上传副本、全量调试图、可重建缓存和已通过新版替代的草稿。先按目录归类，再对风险项核对具体文件。
3. 对旧版整理一张薄的阶段统计表，留下可核对的样本数、时间、模型账本和交付回执。清理前后分别测逻辑大小和磁盘可用空间，检查在制任务和正式交付仍可访问。

### 第二阶段　把复用和期限写进日常流程

1. 用原图内容哈希和版本识别重复输入。在同一授权范围内，优先共享已验证的 OCR、区域定位、干净底图和可复用样式。目标语定稿、排版、最终图片和审核各自绑定相应版本。
2. 审核视图默认使用「原图／去字底图／译图」对照页。整图用于看整体是否协调，小字、品牌、局部修复和疑难区域保留可放大的原尺寸证据。把同一个缺陷的共同观察记一次，各版本保留实际通过或待修情况。
3. 给临时文件、可复用缓存、最新版交付和必要回执分别设保留期。视频的 2 小时、24 小时、7 天和 14 天可作初始参考，具体值按图片项目的补交窗口、用户取件习惯和磁盘预算决定。
4. 工作台默认展示现行方法、同源案例和待处理经验。每次制作保存简短质检与回执。把重复、过时或仅描述流程状态的条目从日常检索中移出，经核对后清理无用正文及索引。手动增量总结新来源，普通结案可以零新增知识。

### 第三阶段　精简下载、回传和结案

1. 下载时复用精确平台资源 ID、已有回执及哈希匹配的本地图片。确需再次下载时沿原资源执行。
2. 审核完整批次中的待交付图片，绑定实际最终版本。按图片 MCP 的真实规则填写命名、标签、共享和设计师信息。允许批量的归属和入库合并处理，独立项并行传输。
3. 把结案点放在全部目标项的真实入库、共享和需求绑定得到核验之时。平台异步处理交给平台。优先复用正式回执或同批读回，遇到缺字段、冲突或未知结果时，只补核对应项。
4. 留下业务需要的确认和恢复证据。图片项目按自己的格式、组图附件关系和平台字段设计测试。YouTube 路由、音轨、帧率及视频时间轴只适用于本次视频项目。

## 图片项目验收清单

| 验收项 | 完成标准 |
| --- | --- |
| 独立性 | 旧目录隔离后，优化版可执行一项新需求并从检查点恢复一项任务。 |
| 知识 | 普通结案新增候选为 0。手动总结能发现确有复用价值的新经验。现行方法、同源案例和冲突待审条目能按各自用途查看。移除旧目录后现行知识仍可打开。 |
| 复用 | 同源多语种样本显示输入只下载一次，共享步骤有命中记录。更换源图或相应参数会使受影响的复用结果失效。 |
| 存储 | 交付目录默认只有最新版，过期及旧中间物能按计划回收。清理前后的可用空间可对账，活跃任务和所需回执仍能读取。 |
| 平台 | 用一批多图验证并行传输和一次批量归属。模拟单项结果未知，其余项目可继续。回执可区分本地上传、平台入库和需求绑定。 |
| 效率 | 工作台分开记录主动处理、等待、总交付时间、token、模型调用或费用、峰值磁盘和 MCP 读写次数。报告同类样本的样本数、平均值和中位数，累积足量样本后再看 P90。 |

## 可复制给图片翻译项目的交办词

> 请用这份视频项目复盘作为参考，先检查图片翻译项目现有知识、任务文件、重复制作、Fireplay 下载与回传。给出当前盘点、空间大户、实际重复开销、保留理由以及各项验收指标。然后按优先级落地图片项目适用的优化。优先处理确定已结案又无依赖的旧产物。同源步骤在授权范围内按输入和版本复用。普通制作只记录质检和交付，经验按需手动提炼。回传用当前 MCP，独立素材并行，相同归属批量写入，留好真实入库和需求绑定回执之后交给平台继续处理。先用一条多图或多语种需求验证，并记录磁盘、时间、token 和平台调用数。
