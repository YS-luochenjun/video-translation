我想要的是一个类似hermes但更简洁的，专业版的更加垂直版本的Agent。

目前的项目需求是：

1. 这是一个，AI和Agent共同运行的部分。目前的小Agent就是本项目；目前的AI就是Codex（最近测试，可以迁移）。
2. 我需要：
   1. 我输入一个视频（例如：英文版本视频），并进行简要的提示词：例如：我想要把视频换成中文版本。
   2. Codex会去在项目中运行
      1. 第一步会去读取项目的Agent.md
      2. 然后进行业务xxxx，调用视频生成模型进行生成或编辑等
         1. 中间进行skill、tool、脚本等内容
      3. 沉淀经验总结（成功经验于失败经验）。为什么要总结经验：
         1. 后续生成内容，和最开始的提示词不符。或codex认为不符合标准。这样需要重新迭代。
            1. 标准是什么样的，由开发者，项目文件，和Codex共同决定，管理。
         2. 生成内容符合标准后，会需要保存偏好（公司整体偏好）类似于hermes或openclaw这样养出一个符合要求的内容。
            1. 标准产生：后续可能会给出历史选择偏好信息，例如给出一个原视频，和一个项目翻译视频，和一个设计师翻译视频。解析哪一个更好
            2. 后续可能也会进行遮蔽测试等
      4. 最后跑通整个流程，目标是：变成一个有判断标准的设计师，可以进行翻译内容。而不是一个共设计师使用的工具。
   3. 最后输出一个AI权衡过后的视频。
3. 目前链路是很明确的，就是codex把视频进行处理，给出提示词，送给专门的视频处理模型。目前的难点在于：
   1. 怎么对视频做处理：是需要如何分段，是否需要对视频音画分开，哪些是关键帧需要强调，什么地方有文字画面音频需要修改等
   2. 怎么进行提示词的给出：是需要把关键词、关键帧附在里面，还是进行分段处理等
   3. 怎么使用视频处理模型：是使用编辑还是生成模式，参数的调整
   4. 怎么对视频的好坏进行分类：需要参考失败经验和各种风格等
4. 目前具体的方案都是未知的还没有定，我也不知道哪一个会更好，我只知道我想出来了部分主链路的方案：
   1. codex解析视频，把每一个需要修改的部分提出，并做成提示词，发送给视频模型，触发“模型编辑”模式进行修改翻译
   2. codex解析视频，提取出有意义的关键帧。对有意义内容进行描述，发送给视频模型，触发“生成”模式进行修改翻译
   3. 等等。我不确定什么会更好，以你的想法也去尝试。尝试结合codex的特点，视频生成模型的特点，项目Agent总结的特点，进行集成分析
5. 目前项目，主要是服务，对一段30s左右（长的可能超过1min，短的可能5s，大多30s左右）的广告，进行从原有的语言，变化为不同其他语言风格的过程。



后续开发过程中需求是：

1. 把本次对话我的输出留着，可能后续需要维护于查看
2. 明确自己每一次都在干什么，对每一次测试结果，需要有批判性的精神，进行总结，寻找是否有更好的内容。
3. 对hermes或openclaw等，可以自我迭代的Agent进行调研，他们是怎么总结用户需要的经验并沉淀的，在每一次运行时是怎么用上的。
4. 需要你对项目进行探索，目前先会出一版本Demo，如果找到了更好的方式内容是允许变动的，但是框架是基本固定的。
