# 信息载体分类、知识衔接与完整音轨检查

来源：项目用户要求修正复查发现的遗漏，明确音频主导、画面文案主导和混合型，旁白与对白均翻译；补齐标签防漏、快速知识记录、必要方法覆盖、旧提示词和长音频检查。保留 Agent 自主选择及理由，更新知识与工作流，验证后一次本地 commit，跳过 Penny。

## 适用条件与行为

- 音频主导：核心卖点或情节由实际讲话承载，先定人声及角色、译稿和声音；辅助画面文案仍翻译。大量对白字幕不单独说明画面文案主导。
- 画面文案主导：独立标题、UI、报价、产品文案承载主要信息，先处理文字与底面/运动；辅助旁白及对白仍配译。
- 混合型：两种载体各有不可省略的重要信息，双清单制作后统一同步。可记录片段例外，Agent 不受固定字数/比例阈值约束。
- 未发现需译语言内容时有据记录 preserve_only；疑似人声仍不明时补证，不能当作没有。角色身份、性别和剧情标签仍由实际观察确认。

三类均翻译全部需译对白、旁白、独白和片尾口播；音乐与非语言音效默认保留。分类决定制作重点，不减少另一条链路的覆盖。

## 执行衔接

新请求带 routing_contract_version=1。routing_assessment 保存主类型、理由及源证据；每个实际需译 speech/visual 域保存所选方法版本、理由、备选、切换与停止条件。普通 plan、新 fast-register 及最终输出都校验记录；旧请求/旧计划不补造历史。

context 从已记录的多个已知 character_id 补多人检索，从待译文字补 onscreen_text，同时说明 feature_origins。每句 speech_role 明确旁白/对白等职责；unknown 不用于推导新角色。必要方法由 reviewed retrieval_role=required 标记，仍先满足 scope、语种、模式和特征，随后完整返回；额外可选方法保留数量上限。读到方法不强制调用对应模型。

快速模式冻结计划、正文和输入版本，work-packet 返回冻结知识、选择及使用反馈待办；knowledge-use 可记录实际采用或未采用。归档携带快照。最终有瑕疵输出也保存独立 selection-only 记录，区分选择证据和执行/质量证明。旧快速计划缺记录时提示重新登记现有配方/产物，不额外付费或继承质量。

旧视觉提示词中的中文配音硬编码移除，目标语言从请求读取；主音频及对比审核明确包含旁白和全部讲话。

音频信号测量完整解码，不再截到181秒。信号窗口/削波统计覆盖全部解码声音，保留波形的相关性在完整时间范围抽样，不能据此声称每个音效无损或语义通过。源解析版本提高以避免复用旧截短测量；快速技术缓存包含音频实现和策略身份。解码失败、超时或不完整不算通过。
