# 视频翻译需求承接说明

在需求面板发起，执行人选择邹彬；有设计师则同时关联，无则留空。填写原片、目标语言及特殊要求。

全天每30分钟检查新需求，按实际翻译内容受理；最多同时推进8个需求，超过上限排队。P0在冲突资源上优先，P1仍持续推进。电脑开机且宿主应用运行时调度生效；不把发起后的发现等待算成制作耗时。

常规需求首轮完整输出暂估约1–1.5小时，不含排队及后续改稿；复杂画面、艺术字/遮挡、多人配音、更多原片或目标语言可能需要更久，也可能因外部模型等待超出此范围。这是少量历史样本的经验参考，不是最低耗时或完成承诺，后续由[真实需求Benchmark](benchmark.md)校准。

历史个案参考：六版约48分钟（两条原片，五种翻译＋一版英语改稿）；十语约65分钟；十二至十四语约76–84分钟。原片数量、内容与起止条件不同，不构成固定的“语种数→耗时”公式；正式公告建议仅保留上述时间范围。

提交覆盖全部原片及目标语言：入素材库、共享需求组、请求YouTube自动上传、语言/产品标签、按编号与语言命名并绑定需求。有设计师时登记真实归属、二创及“二创”标签；无其他关联人时设计师留空。正确受理后的YouTube异步处理由Fireplay负责，不能把“已请求上传”说成“已发布成功”。

依据：用户本次承接标准；config/fireplay-monitor.json、config/fireplay-intake.json、config/fireplay-publication.json。历史样本来自既有真实会话核验，仅作个案说明，未导入前瞻Benchmark，也不为统计重做需求。
