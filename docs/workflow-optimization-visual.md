# 视觉修复与复用优化

总入口见 [workflow-optimization](workflow-optimization.md)。

## 水印修复与原尺寸检查

已将用户对 de2us 去水印的局部认可入库，覆盖范围以[同源参考](../knowledge/cases/de2us-en-watermark-approved-v2.md)为准。新任务遵循[发布者水印政策](../knowledge/rules/publisher-watermark-removal-v2.md)。

| 优先级 | 当前实现 | 仍由 AI 判断 |
| --- | --- | --- |
| P0 | repair-preflight 复用切点检测，分别列出源文字边界、轨迹和完整画面边缘风险；repair-run 执行版本化配方、探针、保护区与同镜头供体 | 实际水印、模糊字入场、产品/姿态边界、供体是否干净、掩模和修复质量 |
| P0 | repair-trials 跨配方累计次数与耗时，缓存不重复计次；中断核对及有理由的有限扩展 | 换路线、解释失败和下一变量；不自动重试付费任务 |
| P0 | visual-pages 按页面实际图层顺序选图，分批返回、提供续看游标；work-packet 返回展示位置和尝试记录 | 真实观察、每项结论、声音和最终质量，展示不等于通过 |
| P1 | 新 run 默认 comparisons-v3：解码流原尺寸 RGBA 裁图，取消逐帧临时 PNG；比较图按实际像素复用，保留逐帧页面和完整覆盖 | 新成片重新绑定和审查；不复制旧 pass，不改现有连续采样标准 |
| P1 | 渲染检查点只跟随计划及绑定资产依赖，新增诊断ASR/图片不改变像素输入指纹 | 真正译文、字体、音轨、时轴和源素材变化仍使对应检查点失效 |
| P1 | 独立知识案例选择必要原尺寸对照、所有明确失败和字幕/音频边界；完整生产审查由交付包负责 | 经验的必要证据、适用范围、反例和正式启用 |
| P1 | run-prune 经原保全/核验门禁，仅回收过时版本的比较图，保留当前成品、底片、配方、账本和全部观察文字 | 不自动清理；执行需当前预览指纹和用户授权 |

旧 comparisons-v2/legacy 证据保持原字节和审核，不自动迁移。v3 的帧号、PTS、源/结果哈希及图层映射保存在每一页的 manifest 和原尺寸查看标题中；比较图内仅保留稳定图层名，便于相同像素共享物理存储。复用索引是线索，仍核对文件哈希和实际像素；新证据目录有自己的完整文件路径，删除旧目录不会丢失新证据。完整性校验仅在单次操作内复用同一硬链接文件的读取，不依赖跨次 mtime 信任。

使用、边界及中断处理见 [修复配方](../agent/workflows/repair-recipes.md)。本轮没有自动水印语义分割或跨源参数迁移，也没有完成 de2us 的音频听感验收。旧的素材专用脚本仍作为历史记录；新通用入口不意味着所有旧脚本都受试验预算控制。

针对重复下载、重复试验、重复编码和机械记录，以下入口按身份和版本复用结果；翻译、声音及视觉标准保持独立。

## 已完成及复用范围

| 优先级 | 实现 | 复用已有能力 | 仍需 AI 判断 |
| --- | --- | --- | --- |
| P0 | 渲染前一次校验全部共享底片，阻止做到一半才发现后续底片未审核 | prepared / visual-audit / batch-approve 原门禁 | 底片是否保真、代表语言是否有代表性；真实逐实例审核 |
| P0 | ASR 统一为 Whisper small，按音频、模型、参数和代码保存并验证转写检查点；只允许下载当前型号 | faster-whisper、本地已有模型、原 ASR 证据接口 | 核对原话和识别歧义，必要时用当前 Gemini 音频分析补充证据；ASR 不负责翻译 |
| P0 | 沿用 tts-packet 定稿生成及任务账本，补充参数结构检查；保留官方可选声音控制字段 | production / model_tasks / KIE 原执行器 | 译稿、语气、语速、声音、参数枚举和实际听感 |
| P0 | 原声提取、UVR 分离、混音按输入指纹复用，混音修改生成独立版本；原混音算法迁入执行器 | separate_local_audio / mix_localized_narration 原算法 | 人声窗口、背景残留、适当语速、音乐和音效是否保留 |
| P0 | 同工作区重任务默认一次一个；开始前检查空间；模型下载及交付复制额外预估所需字节 | run 锁、任务账本、现有串行批次 | 旧临时脚本是否仍运行、是否需要换工作区或清理；不自动删文件 |
| P1 | 本地视觉片段按实际依赖复用；只改音轨或其他片段时不重编码未变视觉片段 | 原 render / prepared / compositor；整片 production 检查点继续使用 | 问题定位、合理切段、修改变量；最终合成、声音选择和实际评审仍执行 |
| P1 | work-packet 从现有状态返回阶段指引、待补证据、未知模型任务和知识入口；不另存一份 AI 进度日志 | status / context / knowledge / batch / resources | 查看命中知识正文、确认适用条件，填写真实观察与因果总结 |
| P1 | 交付归档自动带上新版混音配方及直接依赖，知识继续沿用 deliver / reflect / inbox | 原归档闭包、独立案例与知识保全 | 跨视频推广、因果解释、反例和正式知识启用 |

已有 OCR 缓存、同源解析复用、reuse-neutral、视觉证据复用、visual-notes、production、批次放行和候选复盘继续使用。各入口共用现有执行器、知识和授权合同。`build_repair_master.py` 中仍有素材特定修复规则，不应把它当作通吃所有视频的去字模型。
