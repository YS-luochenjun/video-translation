# 架构决策

1. **AI 主控，项目执行器承载状态。** AI 负责理解、翻译和评价；CLI/stdio MCP 负责可重复操作和证据。宿主可替换，任务和知识留在项目。
2. **按实例选路线。** 本地精确修复、原片模型编辑和重建分别说明代价与风险；具体模型或一次成功不成为默认排名。
3. **时间与区域是任务单位。** 相同词在不同位置或时段算不同实例。声音、品牌例外与画面角色分开声明。
4. **质量绑定实际字节。** 计划、候选、视觉、声音和字幕证据都有身份校验；缺证据保留 pending。同一 Agent 自审、独立评审和用户验收分别记录。
5. **学习先写候选。** 方法与源参考分开检索，启用有来源且范围明确；历史反例持续保留。公司偏好不会由单次结果自动改变。
6. **预算绑定真实请求。** 所有派生 run、短片、语言、模型和返工共享请求账本；每 run 的限制只是附加门禁。未知远端结果先恢复和核账，不通过重建任务重置额度。
7. **安装、临时工作、现场和知识各有生命周期。** 模型依赖放 `.runtime/`，临时内容放 `work/`，现场放 `runs/`，独立交付和知识各自保全。旧规则集中在知识历史区，当前目录只维护一份正文。

执行步骤见 [工作流](../agent/contracts/workflow.md)，实现边界见 [架构](architecture.md)，历史反例见 [维护摘要](history.md)。
