# Codex 与专用模型

2026-10-22 项目拥有者明确要求：文字识别、翻译和图片直接处理交给 Codex；真实音频与必要的视频编辑保留专用模型。此要求替代旧的 RapidOCR 默认、GLM 补查及多视频模型选路偏好。可执行清单只维护在 `config/model-routing.json`，通过 `bin/va.ps1 model-routing` 查看；不对 Codex 设置费用门槛，KIE 请求仍受原有预算与任务账本约束。

## 职责

2026-10-23 用户进一步明确：尽可能由 Codex 发挥判断与执行能力，专用模型只承担真实音视频信号处理。Codex 负责内容理解、翻译、选路、图片编辑、提示词、调用参数、排版、程序操作、结果比较与返工决定。FFmpeg 等确定性工具仍由 Codex 调用，不必为裁切、混音、编码调用生成模型。脚本限制输入、预算、时轴与证据，不预设必须依次尝试的修复算法。

| 工作 | 当前执行者 | 调用条件 |
| --- | --- | --- |
| 文字识别、翻译、图片编辑与视觉审核 | Codex，图片编辑使用宿主图像工具 | 读取实际图片和项目知识后直接完成；方法由 Codex 按内容决定 |
| 真实音频转写 | Whisper small，带 VAD | 需要知道实际对白、语种或时间；无音轨或有效缓存可省略 |
| 音乐、人声分离 | UVR Inst HQ3 | 需要替换混合音轨中的对白；已有合格分轨可复用 |
| 音频理解、原音与成片比较 | Gemini Flash | 无法听音、转写疑点、音乐/音效与对白保留需要补充证据 |
| 配音 | Gemini 2.5 Pro TTS | 定稿后生成目标语言声音，实际混音后建立字幕时间 |
| 视频模型编辑 | Wan 2.7 videoedit | 判断需要连续生成运动、纹理或遮挡时直接选择；无需先把图片/本地方法逐个试失败 |

## Codex 对专用模型的控制

调用前，Codex 根据实际输入确定目的、区间、允许改变的内容、保留对象、预期输出及检查方法；写入已有 packet、配方或定稿，不另建重复表单。返回结果是证据或候选，由 Codex 决定采用范围及是否返工。

| 能力 | 调用前约束 | 返回后判断 |
| --- | --- | --- |
| ASR | 输入实际音轨，按需要选语种提示和片段，保留 VAD、词级时间与置信度；不把预期译稿喂成识别答案 | 核对首尾、低置信度、数字/品牌和疑似漏句；空结果不代表无人声，疑点才用音频理解补证 |
| TTS | Codex 定稿并选声线/风格/语速；`tts-packet` 约束原样朗读、语种、顺序、无配乐/额外台词，程序核验与定稿一致 | 核对实际音频的完整性、发音、时长和衔接，再决定停顿、裁切或适度变速；字幕取实际配音时间 |
| 音频理解/分轨 | 明确输入是原音、配音还是混音，要求带时间的观察及不确定项；只替换所需人声区间 | 分别比较人声、音乐、音效及同步；模型总体评价不替代逐项观察 |
| Wan 2.7 | 输入真实源片段；提示词明确具体文字/区域、进出场与遮挡、保留主体/图形/镜头/时长；仅去字时不添加译文。视觉任务关闭 prompt_extend，保留 origin 音频 | 按源帧比较残字、主体、运动和接缝；可只采用有效局部，模型音轨单独判断。时长/帧率/覆盖不足时拒绝拉长或混帧凑齐 |

约束不等于模型保证遵从。正常播放可接受的轻微视觉差异按 [成品质量](quality.md) 记录并结束返工；漏译、主体变形或听不清不能降为轻微瑕疵。每次返工只改变有依据的变量；沿用原任务恢复、预算与重试上限，未知任务先查询。已有 ASR、配音和视频结果满足输入/定稿/哈希条件时直接复用。

新任务不自动轮换模型。失败先定位输入、定稿、遮罩、音轨或模型结果的问题；同一能力内有界修正，超出能力或预算时保留 pending。图片工具不可用时报告宿主能力缺失，不暗中启动其他 OCR、图片 API 或视频模型。图像生成工具属于 Codex 宿主能力，不在项目另建图像供应商或模型账本。

Kling、Veo、Wan 2.6、Seedance、ElevenLabs、Suno、Gemini 音频 Pro、Piper、Whisper base 和 LaMa 保留历史证据读取/结果复用，不再作为新制作的推理入口。旧任务查询、下载和已核验资产复用不重新提交模型。RapidOCR/GLM 本机安装与历史输出不删除；旧 `bin/ocr.py` 入口转为 Codex 识字工作包。

## 下载、安装与历史资产

`bin/setup.ps1` 调用统一安装器。安装器先读取模型路由并校验完整清单，再安装依赖与模型；不再提供选择旧 ASR 型号或安装旧声音包的参数。已有 Python 时，`.venv/Scripts/python.exe bin/install_dependencies.py --plan` 可只读查看实际清单。

- 本地权重只有 Whisper small 与 UVR Inst HQ3。Whisper 的 VAD 和 ONNX Runtime 属于必要音频依赖；UVR 下载必须与当前注册表的模型身份、路径、地址及哈希完全一致。
- 图片依赖只有 `bin/requirements/vision.txt`，统一放在 `.runtime/deps/vision/`；不从旧 OCR 目录回退加载。基础依赖、ASR 和分轨分别使用 `core.txt`、`asr.txt`、`separation.txt`。
- Gemini Flash、Gemini TTS、Wan 2.7 通过远端 API 调用，项目不下载它们的权重；Codex 图像能力由宿主提供。
- 旧模型文件、旧声音和历史记录保持原样。`config/local-voices.json` 只记录历史声音身份与哈希，没有安装或新合成入口。旧文件缺失、损坏或参数不匹配时停止复用，转到当前能力，不重新下载安装旧模型。

下载的完整性检查、下载锁和断点恢复继续保留。真实网络下载、当前机器安装、隔离源码检查和真实媒体质量是不同验证范围，报告分别说明。

## Codex 图像工作合同

1. `analyze` 后运行 `codex-packet RUN --stage recognize`。命令列出实际图片路径/哈希、任务、当前规则和命中的知识正文。逐图查看，按镜头和文字实例填写观察；原尺寸小字、遮挡和起止边界补实际帧，不用想象补齐。大量帧可用 `--spec` 指定一组图片，覆盖由 inventory 汇总。
2. 修改图片时使用 `codex-packet RUN --stage image --spec inputs/image-task.json`。spec 只有 `images` 和自由文本 `instructions`，不要求先套图片类别。查看原图后使用宿主图像编辑工具；需要透明字层时保留 alpha。将真实工具输出复制到 run 的版本化文件，保留原图。
3. 读取工作包里的规则和知识；参考案例只在其范围内适用。记录实际方法、逐图观察、`knowledge_read`、实际产物路径及未解决问题。运行 `codex-result RUN PACKET REPORT` 绑定输入、上下文和输出哈希。模板见 `agent/templates/codex-visual-task.json` 和 `agent/templates/codex-visual-report.json`。
4. 将识字结果写入 `analysis/inventory.json`，把回执的 `path` 与 `sha256` 放入 `codex_source_result`，仍逐实例保留区域、时间、译文、动作、证据和未完成覆盖。图像结果可作为现有 `reference_image`、参考底图或透明字层输入；在相关 shot 的 `codex_image_result` 填返回的 `path` 与 `sha256`，计划和渲染会重新验证，交付归档保留回执、工作包、输入与图片产物。改变任务、输入图片、知识或产物会使对应工作包失效，重新建立记录。
5. 图片产物登记只是 `needs_review`，不能自动放行底片。静态图不证明运动还原；按实际帧和音频执行原有 `visual-review → visual-release-neutral → render → capture → caption-check → quality`。配音稿不等于真实音频、ASR 空白不等于无人声、同一 Codex 自审不等于独立审查。

工作包由 Python 准备，认知和编辑由当前 Codex 宿主真实执行。项目没有假装存在一个可从 Python 直接调用的 Codex 图片 API；返回工作包不是已经完成识字或编辑。知识阅读回执也不证明实际理解，最终仍靠真实证据审核。

## 保留的程序能力

FFmpeg 抽帧、裁切、排版、透明字层、贴合、混音、编码、缓存及技术门禁继续提供给 Codex。现有修复配方是可选工具，不是固定图片分类或必须逐项尝试的阶梯。需要视频模型时统一 `model_edit`，计划默认映射 Wan 2.7，按其 2–10 秒输入合同安排片段。

无论由 Codex 还是专用模型产生，源片、知识、定稿、图片和实际视频都须可追溯；修改 inventory 后重建计划和审核。用户未要求生成新媒体时，开发验证不提交付费模型任务。
