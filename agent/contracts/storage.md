# 存储、保全与清理合同

现行来源：拥有者2026-10-30要求最终结果按需求／语言／任务组织、默认最新版、最多14天；2026-11-02进一步要求少保存老旧内容、减少制作副本，并授权优化文件清理和知识积累。长期保留少量有价值的方法与必要案例、费用和平台回执；不默认保留整套旧工程。历史一次性重置授权不构成本次清空许可。

保留材料须服务接单、制作、交付或确有需要的费用与平台恢复。历史效率复盘使用阶段汇总。无排障、复用或待处理用途的历史媒体按到期规则清理，避免为清理另存一份成片或工程。旧失败原因可用短记录说明，只有会改变后续做法时才提炼知识或保留必要对照。

## 目录与身份

- `outputs/<需求名>/<语言>/<任务>/final.mp4`是用户查看的交付；编号需求采用真实编号，多原片用任务序号。普通任务可在request填写requirement_name和task_name。
- `outputs/.packages/`保存不可变交付包。默认package_mode=lean，只含一份独立成片和必要JSON审核／请求记录，不复制原片、底片、配音和准备资产闭包。request.delivery_package_mode只允许lean或reusable，并优先于旧keep_reusable_assets标记和配置默认；选择reusable才保存可恢复工程。旧完整包继续兼容。包与展示共用到期规则，不是永久备份。
- `state/delivery-index.json`保存索引和过期历史，浏览页位于`state/delivery-browser`。旧outputs/index.json在实际清理时独立保全并迁出成片目录。已过期历史显示已过期；原先缺包标missing_before_sweep，不谎称本轮删除或可恢复。
- `runs/`是制作现场；`work/runs/<run>`是已登记的任务临时文件；`media/`是可重建源解析库。`knowledge/`保存独立方法／案例，`state/`保存费用、平台提交及清理回执。安装资产、配置与Git不随媒体到期。

## 正常保留与自动清理

交付期限由`config/delivery-policy.json`唯一配置：默认最新版，最多14天；明确request.keep_multiple_versions=true才保留多个版本，仍受14天限制。相同包重导不刷新首建时间，也不能把更旧版本重新覆盖最新版；已标记过期的同身份版本禁止重新落盘，不靠重导复活。新结果核验后原子替换展示。旧包删除后索引保留expired，不再宣称本地可恢复。

制作现场和缓存期限由`config/maintenance.json`配置：

| 内容 | 正常回收条件 |
| --- | --- |
| 已结案run及对应work/runs | maintain --close后2小时，下一轮回收 |
| 已无run的已登记任务缓存 | 闲置24小时，且没有在制任务引用。旧版已删除回执可证明归属，缓冲从回执和最近文件活动中较晚的时间起算 |
| 明确failed/cancelled/aborted或close-failure结案的现场 | 连续7天无文件活动，且没有在制任务引用 |
| media中的源解析缓存 | 连续7天未保存／实际复用，没有保留任务引用，也没有pin |

成功交付后的已登记可重建缓存仍由maintain即时整理；2小时是完整结案现场的缓冲期。安静或旧pending不等于已失败，不能凭年龄删除未结案任务。未知归属work文件保留待分类，不按文件扩展名猜测归属。源缓存的实际使用时钟写state/media-usage，不改写冻结包。

旧任务的交付或结案回执格式异常时，保留该任务、可识别的依赖及关联包，并在预览中列出异常回执路径。其他符合条件的任务照常清理。

`config/storage-policy.json`只维护容量、数量及最低剩余空间阈值。默认优先回收中间物，不因普通容量压力提前删除14天内最新版；只有显式evict_latest_under_pressure=true才允许提前回收已结案包。在制依赖、pin或活动锁会暂缓回收并说明原因；不把暂缓冒称已经清理，续作应将必需资产复制到自己的现场。

新run落盘前检查源文件大小与最低剩余空间之和。HTTPS接入在开始下载前检查剩余空间，在创建run前再按实际文件大小检查。目录容量和数量阈值继续用于清理规划。该检查按当时可用空间判断，后续制作中间文件的空间由各阶段实际占用决定。

重渲染、审核和其他重负载阶段同时遵循工作区磁盘预留。片段及最终合成按像素数、帧率和时长估算写入空间，完全命中片段缓存时直接复用。无损修复母版按解码帧数与像素数检查写入空间，完全命中母版时优先链接已核验的产物。

自动执行要求本机`config/storage-authorization.local.json`的workspace精确绑定和automatic_cleanup=true。新机器从example配置自己的授权，reset_existing_data保持false。常规storage-plan／storage-sweep预览只读，执行使用当前预览指纹：

```sh
python bin/va.py storage-sweep
python bin/va.py storage-sweep --execute --expect <本次预览指纹>
python bin/storage_daily.py
python bin/storage_daily.py --execute
```

每日入口默认只读，--execute才删除；没有授权或已有清理执行器时返回deferred。规定每天上海18:30运行，制作阶段按配置间隔增量检查。Windows可用`bin/project-storage.ps1`的Install/Status/Uninstall管理唯一工作区任务，Install和Uninstall需要-Execute；与应用定时任务二选一，不能重复安装。系统触发器设置错过后补跑；配置、代码或安装计划不代表本机已安装成功，真实状态和运行回执分别核实。运行保全保存证据包和恢复材料，经验总结由用户手动触发。单轮候选按当前预览处理，不保留旧的每次只清3个run的限制。

macOS 可用单一 LaunchAgent 定期唤醒 `python bin/storage_daily.py --execute --scheduled`。脚本使用上海时间和上次执行回执，按 `lifecycle_check_seconds`（默认一小时）检查，并保留上海18:30每日检查点。活动锁或预览变化导致暂缓时，下次唤醒重新检查。

多个制作阶段同时结束时，只由一个执行器发起增量维护检查。预览后如发现制作已恢复，暂缓本次清理，下次重新预览。模型提交、音频分析及轮询完成后先返回任务与费用回执，全项目清理由其他阶段或每日维护执行。

增量及每日维护会从当前内容版本的 Fireplay 已核验绑定 outbox 恢复漏掉的本地结案：逐语种匹配真实素材 ID、成片哈希、独立包、源和 run，核验既有门禁后执行本地收尾，不调用平台、不重传、不重新制作。未受理语种、发布阻塞、重新打开的制作及不匹配版本不自动结案。只读入口列出候选，执行入口记录实际收尾结果。该收尾仅使用本 run 的锁及已有包，不等待其他原片的渲染锁。定时整理遇到其他原片制作时，可使用 `closed_runs` 模式回收已超过2小时的独立结案现场及所属缓存。正在制作的 run、同源现场、任何保留任务的依赖和人工pin继续受保护；活动锁缺少明确run身份、计算锁归属不明、活动引用记录不完整时暂缓。执行前后核验候选指纹与必要记录，全局清理锁暂时管理新阶段的准入，已持有run锁的执行器继续完成本阶段。共享源缓存、交付包和终态任务仍在全项目空闲时统一回收。

## 执行与重复保存

同源接入与解析恢复使用核验后写时复制（macOS 文件系统支持时），否则回退独立副本；保持可独立修改，不对可写源解析文件使用硬链接。生成字体按源哈希、真实字面及渲染转换身份复用现有 run 内已经生成的字体；索引仅记录可重建位置与哈希，源 run 回收后按需重建，不额外保留永久字体副本。确认替换片已审核通过后，通过既有 `run-prune-versions` 及时回收明确被替代且无活动依赖的旧视频；不在制作中仅凭名字或年龄自动删除。

执行器先检查活动锁，冻结候选路径、文件元数据、完整策略、索引及保留任务的依赖。独立保全必要文本记录，核对指纹后删除；归档从读取源文件到登记索引全程共用run锁，但不撤销原结案状态；结案生产者、新任务及归档均在取得自身锁后再次检查全局清理锁。在制任务的跨run引用按传递关系保护，指纹变化必须重新预览。知识审计前后通过；未知费用保留原预留、真实任务ID和响应，删除媒体不结清费用、不改变质量异议或用户验收。

- 同一需求／语言／任务只有一个默认final入口；相同归档重试不新增copy、backup、final2，不改变业务身份或首建时间。
- 成片必须脱离run仍可读，不能硬链接到可变run。不可变包内相同SHA256资产及正式展示优先硬链接；不支持时复制并校验。禁止原地修改展示文件，改版必须重新制作并原子替换。
- 相同源解析按哈希和提取参数核验复用。源观察有修订时，保留独立清单和观察正文。同一源及提取参数下，字节相同的缓存资产在不可变快照间优先硬链接，不链接可修改的run。快照可各自核验和到期。新语言仍独立定稿、配音和审核。需要修改的副本放所属work/runs，禁止额外整目录备份。默认lean没有源／准备资产恢复资格；archive-verify通过只证明包完整，不等于可恢复生产。
- 候选片转最终片及经批准的同源底片复制在 macOS 优先采用写时复制，保留独立文件并核验字节。相同成片重试复用现有文件，其他文件系统可用普通复制。同源底片引用目标任务已核验的源片。
- 新版成片总览用一次解码生成分页拼图及一张单帧。分页索引记录采样时间和范围。既有逐帧总览继续沿原布局恢复，首尾、镜头接缝、字幕及全幅实际审核证据保持原覆盖。同一视频版本中由同一抽帧结果产生的证据标签可共用不可变图片。
- 已结案缓冲期允许回收执行器登记的废弃无损母版。仅处理整片对应单镜头且新版底片通过完整时长及评审核验的任务。旧母版须早于当前底片、哈希匹配、未获批，且无本任务或其他保留任务的路径或哈希引用。保留配方、来源和审核记录。其他产物走常规结案或明确的版本清理流程。
- 失败或被替代的渲染，等同一任务的当前正式替换片通过质量检查、独立包核验且无在用引用后，即可用 `run-prune-versions RUN SPEC` 清理，无需先生成完整恢复副本。规格填写 `replacement_sha256`、旧版路径和哈希、判定理由、必要的文字记录及证据范围。确有复用价值时才随 `evidence` 保留局部截图或声音，普通返工可省略。执行沿用预览指纹和本机授权。仍在排查或只有 `best_available` 的任务沿用常规结案与清理条件。
- 知识只独立保存有用途的必要对照，不复制整片作永久备份；不跨公私或授权范围去重。临时副本登记用途和退出条件，保全记录不复制所有待删视频。
- 已核验上传、入库、素材详情和绑定回执，且重新计算的媒体哈希匹配时，归档跳过 `work/runs` 中的临时 Base64 上传参数文件。实际回执和未知操作的材料继续保留。
- 清理后移除空展示目录。回执分别报告逻辑字节和磁盘实际净变化；硬链接及并发系统写入下两者不同。当前没有全项目跨包物理去重，不作此宣称。

## 结案与一次性重置

外部提交和必要记录完成后执行`maintain RUN --close`。本机已授权的新布局核验独立交付后写入正式视频哈希结案标志；不再额外建立永久整片恢复副本。旧逐run入口仍走run-preserve → run-delete预览及指纹，不把生命周期执行器当force开关。

storage-reset只适用于用户当前明确确认所有旧任务已完成并要求清空、且本机另有一次性reset_existing_data授权的情况。它可清空runs/work/outputs/media，保留知识、state、费用、平台历史、配置、Git与安装资产；执行后消耗许可。定时入口永远不调用reset，本次优化不执行重置、不删除当前生产数据。
