# 存储、保全与清理合同

现行来源：项目拥有者2026-10-30要求outputs按需求名／语言／任务存放最终文件，默认只保留最新版，结果最多14天；runs、work等超过一定量清理，并明确确认现有制作任务均已完成，授权一次清空旧制作数据重新开始。旧的“交付包永久保留、不按年龄删除”不再适用。知识、账本和平台回执不随视频到期。

## 目录与身份

- `outputs/<需求名>/<语言>/<任务>/final.mp4`是用户查看的交付；编号需求采用真实需求编号，多原片任务用原片序号，不把源哈希当需求名称。普通任务可在request填写requirement_name和task_name。
- `outputs/.packages/`隐藏保存独立恢复包，正文、配方、审核和实际媒体按manifest冻结；它们与可见最终文件一起受保留政策限制，不是永久备份。最终展示文件仅链接到不可变包，不链接可变run。
- `state/delivery-index.json`保存交付索引和过期历史，浏览页位于`state/delivery-browser`。源SHA256仍是身份，不因改目录混并需求。同源不同需求分开，同需求各原片任务分开。
- `runs/`是当前制作现场；`work/runs/<run>`是该任务临时文件；`media/`是可重建源解析。`knowledge/`保存独立方法/案例；`state/`保存费用、操作、平台提交及清理回执；`.runtime`、配置与Git为安装/工程资产。

## 正常保留与自动清理

唯一交付配置是`config/delivery-policy.json`：默认展示最新版；用户明确要求多个版本时request.keep_multiple_versions=true，仍最多14天。重复归档同一包不延长其首建时间。新结果独立核验后原子替换最终展示；旧包由生命周期执行器删除，旧索引保留expired状态，不能再宣称本地可恢复。

`config/storage-policy.json`提供runs、outputs、media数量/容量及最低剩余空间阈值，`config/maintenance.json`提供work容量及检查间隔。`storage-plan`继续只读；实际执行使用storage-sweep。周期任务和制作阶段成功后的增量检查会处理已到期包、未要求保留的旧版本，以及生产者已maintain --close的现场/对应缓存；容量不足时可提前回收已结案包。未结案任务、活动锁及未知归属缓存继续保留并报告，不能按扩展名猜测删除。

自动删除还要求本机`config/storage-authorization.local.json`的workspace精确绑定和automatic_cleanup授权；新机器从example配置自己的授权，不继承别人的一次性重置许可。技能/调度不重复维护容量或天数。每天上海18:30的独立存储任务继续执行；制作阶段按配置间隔检查容量，无需用户反复提醒。

```sh
python bin/va.py storage-sweep
python bin/va.py storage-sweep --execute --expect <本次预览指纹>
```

执行器检查活动锁，冻结明确路径、文件元数据及政策指纹，独立保全JSON/任务/字幕/脚本等记录，再核对指纹后删除。全局清理锁阻止新制作进入；知识审计前后均须通过。账本同步后费用未知仍按原预留保存，删除媒体不会结清费用，也不会改变质量异议或用户验收。实际净释放以磁盘可用空间变化报告，逻辑字节不等于可回收空间。

## 重复保存规范

来源：项目拥有者2026-10-30明确要求规范重复保存文件。先区分相同字节与相同业务用途，不凭文件名或大小判重。

- 同一需求／语言／任务只有一个正式展示入口`final.mp4`；重试导出相同实际视频须复用已验证的包和索引，不另建copy、backup、final2等目录，也不刷新到期时间。不同需求、原片、语言或用户明确保留的版本分别记账，不能为省空间合并业务身份。
- 制作现场是可变工作区，交付包是经哈希核验的不可变快照。交付必须脱离run仍可用，所以允许这一份有明确用途、最多14天的独立快照；不能把交付硬链接到仍可改写的run文件。结案后按生命周期回收制作现场。
- 同一不可变包内，相同SHA256的资产优先硬链接；正式展示优先硬链接到包内成片，避免占用第二份完整视频空间。文件系统不支持时允许复制并核对哈希，副本与原包共用到期和删除规则。硬链接的多条路径不代表多份磁盘数据，不按路径字节之和宣称释放空间。修改展示文件也可能修改包，必须重新制作并原子替换，禁止原地写入。
- 相同源视频、解析、模型结果或准备资产先查现有精确哈希、作用域和有效性；可核验复用就引用其记录，不因重试重新下载、生成或上传。需要修改的恢复工作副本必须独立复制，放在所属`work/runs/<run>`，保留来源并随任务清理；不在桌面或outputs旁额外存一套。
- 知识只长期保存必要的独立证据，不复制整片当作知识备份。公有与私有证据、不同授权范围不做跨边界自动合并。来源原文、不可变历史和账本即使内容相似也保留追溯关系，现行方法只维护一个入口；同义且同scope才合并知识。
- 临时副本必须属于具体任务并说明用途、源哈希和清理条件；无明确用途的整目录备份禁止新建。清理记录保留必要元数据，不把所有待删视频再复制到state。任何去重删除仍走明确清单／指纹与现行保全门禁，不按扩展名批量删除。

当前自动去重范围为包内资产、展示文件和相同归档重试；跨包的同源大文件共享尚未实现，不宣称已实现全项目物理去重。此类副本随结案／最新版／14天政策回收，后续共享存储必须先验证引用计数、删除独立性和公私边界。

## 结案与临时目录

生产者完成外部提交和必要记录后执行`maintain RUN --close`。本机已授权的新布局核验独立交付包后，写入绑定正式视频哈希的结案标志，交由生命周期保全记录并回收现场，不再额外生成永久整片恢复副本；未启用新布局的旧逐run保全/删除入口继续有效。知晓未知费用不要求永久保留所有大视频，账本、真实任务ID/响应和原始记录必须独立保存，知识案例不能依赖随后到期的媒体。

复用能力归src/bin，素材参数归run；不要每次复制新专用脚本。普通未归属work文件需要先分类；共享安装资产归.runtime。旧run-delete仍按run-preserve → 新预览 → --execute --expect，不将新的到期执行器作为它的force开关。

## 一次性重新开始

本次用户已明确确认全部现有制作完成。单独的storage-reset在本机一次性reset_existing_data授权下，明确预览并清空runs、work、outputs、media四个生产数据区域。保留全部knowledge、state、账本、Fireplay提交历史、配置、Git及安装资产。删除前独立保全生产记录，旧交付标expired，未知费用不归零；不保存整片副本假装释放空间。此后不能恢复已删除原片/成片，只能查知识、记录或经授权重新取得来源。

```sh
python bin/va.py storage-reset
python bin/va.py storage-reset --execute --expect <本次预览指纹>
```

重置授权执行后即消耗，不会进入定时任务。新运行不得自动重做旧Fireplay基线或重置请求预算。今后的清理继续用有范围、有指纹的生命周期入口，禁止额外手工递归清空项目。
