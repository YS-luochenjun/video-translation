# 音频本地化

当前新任务模型以 [模型分工](model-routing.md) 和 `config/model-routing.json` 为准：音频理解仅 Gemini Flash、配音仅 Gemini TTS、视频仅 Wan 2.7。旧供应商与具体素材试验已归入 [维护历史](../../docs/history.md)，不构成新提交入口。


用户确认的默认要求（2026-10-19）：每次保留原背景音乐与音效，翻译对白等语言内容。不因当前 AI 不能听音而删去声音或忽略这项要求；无音轨的源文件保持无声，另有明确授权时才补配乐。当前来源是本项目用户的直接要求，不是模型自评分推导的偏好。

## 解析与选路

多人对白/短剧先读 [固定角色声线](../../knowledge/rules/short-drama-character-voices-v2.md) 与 [声音事件及时间处理](../../knowledge/rules/short-drama-audio-scenes-v2.md)；单人口播读 [实际混音与分歧](../../knowledge/rules/method-spoken-caption-verification-v4.md)。源轮次和画面事件约束时间，静音处理→确认空隙→有限变速→精简定稿及同声线补录；每步以实际清晰度和完整发音决定，不能截句跨人。

用户明确必需目标语音频时，音频不可用须直接报告，完整字幕不替代配音交付。身份疑点、漏句、临时供应商故障与真实能力边界分别处理，按角色方法记录降级范围；最少男女声并不免除同角色一致检查。

`analyze` 保存音轨、信号强度、静音比例与时间窗口到 `analysis/audio-source.json`。音轨存在不等于有声，信号有声不等于已识别人声。来源没有音轨时明确记录；不能从字幕推断已经听到对白。

`audio-analyze RUN --execute` 将真实 WAV 交给 KIE Gemini Flash，区分背景音乐、非语言音效和对白，保存带时间戳的转写与模型归因。调用有任务账本和预算；API 返回不明时保留状态，不能自动重复请求。它是外部模型的音频理解，报告不能写成 Codex 亲耳听过。

- `preserve`：已有证据确认没有需翻译的人声，交付时从原视频重取完整音轨，保留音乐与音效；视频模型产生的声音不替换原混音。
- `model`：由 Wan 2.7 原片编辑同时翻译对白，使用 `audio_setting: auto`，从模型原始结果提取音轨后拼接、混回成片。模型音轨缺失时阻止渲染，不回退到静音或原外语对白。该参数允许生成音频，不保证翻译或分轨保真，必须检查结果。
- `replace`：导入已审完整译后混音，保留背景音乐和音效；配音、背景与音效的混合由音轨提供方负责，文件与计划绑定哈希。
- `mute`：源片有音轨时须有明确静音授权，不是故障回退路线。

人声用时间戳、原文、译文和证据记录。控制 AI 无法听音时，仍向模型发送保留音乐/音效、翻译对白、保持说话角色与时序的要求。可以将未知人声标为 pending，进行明确的模型试验；pending 不构成交付通过。实际音频转写/听审尚未完成时保留未验收状态。

口播与对应字幕共用 `speech_segments[].target_text`；TTS 请求填写有序 `speech_ids`，执行器在付费提交前核对稿件。独立混音程序也核对每句定稿与覆盖。实际字幕时轴使用裁切/变速/偏移之后的完整混音，操作与成片同步门禁见 [agent/contracts/captions.md](captions.md)。

## 执行与核验

所有模型提示词都包含声音约定；`packet` 同时显示音频策略与供应商实际参数。仅写提示词不能替代音轨执行。视觉处理中间文件允许无声，最终 `render` 明确选择音轨并保存 `outputs/audio-selection-*.json`，包含原片、模型任务、选中音轨和哈希。

模型返回音频若仅末尾短缺不足0.3秒，可补齐时间轴尾部以防后续片段整体提前，保留每段 `model-audio.json` 的实际短缺量；不改变音乐速度，也不声称补回了缺失的音乐/音效。明显短缺或实际可听断点仍须打回。

`capture` 导出成片 WAV 与 `audio-report.json`。`quality` 重新测量实际视频：音轨有无、近静音、音频时长、严重削波、明显降音量；原音保留路线还比对波形、时移与掉音。保留项失败会打回，不能因总分高而放行。

`audio-analyze RUN --candidate --execute` 将原音和实际成片音频一起送审，要求先原样转写成片，再检查原配乐/音效、译文完整性和同步，保存到该视频哈希对应的 `audio-model-review.json`。重新 `capture` 将报告纳入证据。已存在的音频模型报告若指出配乐改变、音效丢失、漏译、外语残留或不确定，机器门禁会拦截；不能用主控的高评分覆盖。

这里的音频同步只涉及声音时间轴和衔接。该请求没有提供画面，不能证明字幕与口播一致；字幕另用 `caption-sync.json` 同时审声音和画面。粗粒度 ASR 的一句时间范围也不能直接当作逐词字幕对齐。

译后或模型音轨另需 `review.audio_checks` 对音乐、音效、对白翻译和同步逐项给出方法、成片音频证据与结论。对白未知/未核对、外语残留、音乐或音效丢失均不能通过。ASR/听审负责语义，波形检测只证明信号与保留关系；配音不等于口型已对齐。

## 独立配音与转写

`tts-packet` 从已定稿的有序 `speech_ids` 准备请求；`model-task` 预览后才按已有授权提交。配音、音频理解和视频任务共享请求预算；远端状态未知时先恢复原任务。原始响应与计费回执先保存，再解析业务内容。

`bin/asr.py RUN` 转写实际音轨，`--audio` 可检查指定运行音轨；记录语种、分句、模型和音频哈希，不将预期译稿当作已听到的内容。ASR 可以辅助核对对白覆盖，发音、音乐音色、音效和口型仍需实际审核。

配音裁切、变速、偏移和回混记录在实际产物的 provenance 中。字幕按最终混音重新对齐；不同模型产生的时长、分轨延迟和旧素材参数不能直接沿用。

## 全部语言内容与长音轨

音频主导、画面文案主导和混合型都翻译可辨对白、旁白/解说、独白及片尾口播；语音职责用 speech_role 记录，音乐/非语言音效默认保留。画面人数不等于说话人数，预设名称不证明音色/性别。视觉任务仅修画面时，声音交给独立链路，目标语言从请求读取。

技术测量完整解码单声道16kHz音轨，报告 measurement_scope=complete_decoded_audio；所有半秒窗口、时长、削波/掉音和保留波形比较覆盖全音轨，不再停在181秒。解码失败/超时须报告，不能给部分测量填全片通过。语义、旁白/对白完整度、音色和字幕同步仍需真实审核，完整波形不是完整翻译证明。旧源解析版本不自动复用其可能截短的测量；旧费用与质量结论保持历史。
