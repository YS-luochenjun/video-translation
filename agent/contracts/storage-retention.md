# 存储保留与自动清理

总入口见 [storage](storage.md)。

## 正常保留与自动清理

交付期限由`config/delivery-policy.json`唯一配置：默认最新版，最多14天；明确request.keep_multiple_versions=true才保留多个版本，仍受14天限制。相同包重导不刷新首建时间，也不能把更旧版本重新覆盖最新版；已标记过期的同身份版本禁止重新落盘，不靠重导复活。新结果核验后原子替换展示。旧包删除后索引保留expired，不再宣称本地可恢复。

制作现场和缓存期限由`config/maintenance.json`配置：

| 内容 | 正常回收条件 |
| --- | --- |
| 已结案run及对应work/runs | maintain --close后2小时，下一轮回收 |
| 已无run的已登记任务缓存 | 闲置24小时，且没有在制任务引用。旧版已删除回执可证明归属，缓冲从回执和最近文件活动中较晚的时间起算 |
| 明确failed/cancelled/aborted或close-failure结案的现场 | 连续7天无文件活动，且没有在制任务引用 |
| media中的源解析缓存 | 连续7天未保存／实际复用，没有保留任务引用，也没有pin |
| 独立且已结束的测试目录 | 登记结束时间和独立摘要，2小时后由维护轮回收，包括生产期间符合独立性条件的 scoped 清理 |

独立测试优先使用自动退出的临时目录。必须保留到测试结束后才能整理的 `work/<测试名>`，结案时在本机 `state/maintenance/retired-work.json` 的 `entries` 登记 `path`、带时区的 `completed_at`、独立 `summary` 路径和 `summary_sha256`。摘要放在 `work/state`、`state` 或 `docs`，记录测试结果和必要费用回执。登记后目录或摘要变化、在制依赖或登记损坏时暂缓。其他未完成任务的异常回执中能识别的路径也纳入依赖核对。回收仅保留摘要与删除回执，避免把整个旧测试工程复制到历史记录。

旧本地试制若曾使用主工作区的 `runs/`，其独立 JSON 摘要和登记项可同时列出 `run_sources`（精确 run ID 到源哈希）。有生产绑定、正式交付包、供应商任务、未结算费用、活动或人工保留要求的 run 继续按原生命周期处理。仅保存试制结果的孤立输出目录亦可按登记回收。存在保留 run 或在制引用时，相关试制工作目录随之暂缓。

成功交付后的已登记可重建缓存由交付、定稿阶段的维护钩子或显式 `maintain` 整理。中间制作阶段跳过自动目录及账本维护扫描，实际清理仍在交付或定时维护时执行。2小时是完整结案现场的缓冲期。安静或旧pending不等于已失败，不能凭年龄删除未结案任务。未知归属work文件保留待分类，不按文件扩展名猜测归属。源缓存的实际使用时钟写state/media-usage，不改写冻结包。

旧任务的交付或结案回执格式异常时，保留该任务、可识别的依赖及关联包，并在预览中列出异常回执路径。其他符合条件的任务照常清理。

`config/storage-policy.json`只维护容量、数量及最低剩余空间阈值。默认优先回收中间物，不因普通容量压力提前删除14天内最新版；只有显式evict_latest_under_pressure=true才允许提前回收已结案包。在制依赖、pin或活动锁会暂缓回收并说明原因；不把暂缓冒称已经清理，续作应将必需资产复制到自己的现场。

新run落盘前检查源文件大小与最低剩余空间之和。HTTPS接入在开始下载前检查剩余空间，在创建run前再按实际文件大小检查。目录容量和数量阈值继续用于清理规划。该检查按当时可用空间判断，后续制作中间文件的空间由各阶段实际占用决定。

重渲染、审核和其他重负载阶段同时遵循工作区磁盘预留。片段及最终合成按像素数、帧率和时长估算写入空间，完全命中片段缓存时直接复用。无损修复母版按解码帧数与像素数检查写入空间，完全命中母版时优先链接已核验的产物。

自动执行要求本机`config/storage-authorization.local.json`的workspace精确绑定和automatic_cleanup=true。新机器从example配置自己的授权，reset_existing_data保持false。常规storage-plan／storage-sweep预览只读，执行使用当前预览指纹：

```sh
python bin/va.py storage-sweep
python bin/va.py storage-sweep --execute --expect <本次预览指纹>
python bin/storage_daily.py
python bin/storage_daily.py --execute
```

每日入口默认只读，--execute才删除；没有授权或已有清理执行器时返回deferred。规定每天上海18:30运行。Windows可用`bin/project-storage.ps1`的Install/Status/Uninstall管理唯一工作区任务，Install和Uninstall需要-Execute；与应用定时任务二选一，不能重复安装。系统触发器设置错过后补跑；配置、代码或安装计划不代表本机已安装成功，真实状态和运行回执分别核实。运行保全保存证据包和恢复材料，经验总结由用户手动触发。单轮候选按当前预览处理，不保留旧的每次只清3个run的限制。

macOS 可用单一 LaunchAgent 定期唤醒 `python bin/storage_daily.py --execute --scheduled`。脚本使用上海时间和上次执行回执，按 `lifecycle_check_seconds`（默认一小时）检查，并保留上海18:30每日检查点。活动锁或预览变化导致暂缓时，下次唤醒重新检查。

全项目清理由独立定时任务或手动入口执行。制作阶段只处理本 run 的必要维护。创建 run、制作和归档遇全局清理锁时，在取得 run 锁进入实际操作前最多等待45秒。锁释放后继续原命令。到时仍有锁则报告该次操作尚未开始。参照[持续执行](../workflows/fireplay-intake.md#持续执行到平台受理)恢复。

交付目录共同索引写入使用独立互斥锁，短时竞争最多等待30秒，取得锁后重新读取最新索引再登记。清理回执的 `global_lock_seconds` 记录取得全局锁至删除和索引处理结束的时间。删除后的知识复查在释放全局锁后执行，清理前的审计、保全和指纹复核仍在锁内。

定时维护会从当前内容版本的 Fireplay 已核验绑定 outbox 恢复漏掉的本地结案：逐语种匹配真实素材 ID、成片哈希、独立包、源和 run，核验既有门禁后执行本地收尾，不调用平台、不重传、不重新制作。未受理语种、发布阻塞、重新打开的制作及不匹配版本不自动结案。只读入口列出候选，执行入口记录实际收尾结果。正常 `maintain --close` 和自动恢复均可在其他原片渲染期间完成本 run 的归档、核验及结案登记。实际删除仍走清理门禁。定时整理遇到其他原片制作时，可使用 `closed_runs` 模式回收已超过2小时的独立结案现场及所属缓存。正在制作的 run、同源现场、任何保留任务的依赖和人工pin继续受保护；活动锁缺少明确run身份、计算锁归属不明、活动引用记录不完整时暂缓。执行前后核验候选指纹与必要记录，全局清理锁暂时管理新阶段的准入，已持有run锁的执行器继续完成本阶段。共享源缓存、交付包和终态任务仍在全项目空闲时统一回收。
