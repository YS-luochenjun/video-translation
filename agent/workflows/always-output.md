# 尽力改进，最终输出翻译视频

来源：2026-10-23 用户明确要求此规则适用于所有后续任务，评分用于步骤中的重试，做不好也必须输出最终翻译视频。默认策略为 `config/workspace.json` 的 `output_policy=best_available_required`。

## 制作与结束条件

1. Codex 完成全时间轴的文字和口播翻译，尽早用已有源片、本地排版和声音资产制作完整候选，再逐步改善去字、贴合和音质。候选允许带瑕疵，翻译覆盖与瑕疵分别记录。
2. 根据实际质量决定是否有价值返工；沿用总预算、任务笔数与有界返工。某条去字路线失败只结束该路线，不结束整个翻译任务。底片无法达到严格标准时，选择当前最好且完整的底片，或者原片局部处理加透明译文字层；沿用原容器，不新增不透明文字条。局部模糊按[底面与运动难度](../../knowledge/rules/content-aware-text-restoration-20261026.md)逐实例判断，静态底面优先自然重建，复杂运动可更早评估兜底；最终必须输出本身不构成模糊理由。
3. 配音失败先复用匹配的已有声音并有界重试。用户明确要求必须有目标语音频（包括当前多人短剧要求）时，字幕不构成音频兜底；仍无可用声音则明确报告语言、失败阶段及未完成项，保留已有完整保底和候选，不把无配音候选标为满足请求。只有用户允许字幕兜底的任务，没有可用目标配音时才用完整目标语字幕交付，保留原音乐/音效并明确说明原声保留或配音缺失。不以静音、半句配音或漏译代替完成。源片不含字幕也可在这一兜底路线增加口播翻译字幕；在inventory明确标记 fallback，而不改写原片分类。
4. 正常完成质量检查并通过时使用原 `deliver`。达到尝试/预算/能力边界后，Codex 选定当前最好的完整实际视频，按 [收口模板](../templates/finalization.json) 填 `review/finalization.json`，运行 `finalize RUN`；`deliver` 也会识别该文件进入同一路径。分数不足、未完成独立审核或已知外观问题不阻止此输出。
   已有逐镜头 `prepared_video` 和 `surface_typography` 时，运行 `compose-best RUN` 按原帧数拼合透明译文字层与当前最好底片，复用已有替换音轨。无底片时使用同一时刻原片；无译文字层时由 Codex 先制作。该入口不要求底片质量通过，不重新调用模型，生成完整候选后仍需确认翻译覆盖再 finalize。
5. `finalize` 核验源、清单、实际视频、翻译覆盖声明与证据，完整解码并检查全时长、尺寸和音轨，输出根 outputs 包和 `final.mp4`。状态为 `delivered_with_issues`，原 quality/failure/hold 保留，不能称质量通过或自动复用为已批准底片。归档遇到错误时保留已编码的 run 内 final.mp4，修复归档并继续，不重新付费生成。
6. 有符合用户硬性音频条件的视频时，最终回复给可播放的视频和简短瑕疵说明；音频必需且不可用时直接说明真实阻塞，不以“未通过，所以没有视频”结案。源片损坏/不可访问或无法写出可播放文件属于真实执行阻塞：先恢复输入、解码或输出位置；不能伪造文件，也不能把原片重命名声称已翻译。

框架能核验文件与记录，不能自动证明翻译语义。Codex 必须对实际成片确认文本和口播的译文已呈现；`speech_mode=subtitled` 不代表已配音，声明的瑕疵也不代表用户验收。

新请求从工作区默认记录 `require_target_audio=true`（有人声需翻译时生效）；用户明确允许字幕兜底才将该请求改为 false 并保留来源。续作中收到必需配音要求时同样更新请求并重建相关绑定。历史请求缺少字段不自动改写，但 Agent 仍须遵守该次明确要求。`finalize` 阻止必需配音请求以 subtitled 收口；实际语种和完整性仍由真实音频证据证明。

## 交付表述与收尾

用户于 2026-10-23 明确要求：实际译片生成后，对需求提交使用“<语言>视频成功生成”；素材名称为 `<需求编号>-<locale>`，文件名追加 `.mp4`。生成、平台关联和 YouTube 上传状态分别按实际回执记录；内部审核结论继续保存。接口没有备注字段时不覆盖原需求描述，不声称已写入不存在的备注。

完成本次所有外部提交及记录后执行 `maintain RUN --close`，按 [存储合同](../contracts/storage.md) 增量整理。清理暂缓不阻断最终译片输出。

Fireplay 网页上传本地视频时，“普通上传视频，不自动上传 YouTube”保持不勾选，配置为“自动”，才会创建自动上传任务。MCP 的 R2 入库成功不能代替上传任务回执；需要时使用网页上传入口，分别记录素材 ID、需求绑定 ID 与上传任务 ID。发现网页和 MCP 身份不同时保留真实操作人，避免将不同素材记录混为一条。任务已受理后交给平台执行；用户要求停止检查时停止轮询，不自动重投。
