# 快速交付（默认）

所有后续请求遵守[最终输出](always-output.md)：失败门禁阻止的是质量通过，返工结束后仍须输出完整翻译视频，状态为已输出/有瑕疵。明确必需真实配音但不可用时，按最终输出合同的音频例外如实报告；其他情况不得用失败报告替代视频。

来源：项目用户于 2026-10-23 明确要求默认快速交付、减少试验/重复检查/归档等待。配置为 `config/workspace.json` 的 `default_delivery_mode`；旧请求不自动迁移。严格模式仍适用于用户明确要求的逐像素保真或既有严格候选。

## 执行

1. 优先读取一次 `work-packet`，复用按源哈希核验的解析、分轨和定稿。开始时检查授权与总账本；执行器每次付费原子预留/结算，无须主控反复读整份预算。未知费用继续占位，额度按真实用户指令修订，不通过换 run 补充。
   先看工作包的 `reusable_packages`：从根 outputs 的完整包恢复可用素材，再考虑 runs 中未归档资产；reference/revise 包只作参考，复用不继承语言审核。调用专用模型前读 [模型控制](../contracts/model-routing.md)，Codex 自主选路，不必逐项试完本地方法才用 Wan。
2. 全时间轴建立文字/语音清单，单独检查开头、结尾与 CTA。ASR 空结果不能证明无人声。不确定片段才追加音频理解。
3. 源文字按[底面与运动难度](../../knowledge/rules/content-aware-text-restoration-20261026.md)选路：简单静态界面自然重建；复杂运动/遮挡更早比较最小局部模糊兜底。路线在代表性困难片段验证，最多两次有明确变量的试验，初始选路时间盒五分钟；依据实际内容和主体风险提前停止，不必穷尽方法或反复付费。切换兜底不重置限额，静态图认可与运动审核分别记录。
4. 普通文字允许字体、装饰差异与轻微局部修复痕迹，继续遵守既有“不新增实心文字条”的用户要求，使用透明字层。原箭头、爱心、主体、音乐音效应保留。按原始帧和时刻合成；短模型片段拉长、混帧补运动不能用于快速交付。保护区域取对应源帧。复用能力放 `src/`，素材特定坐标与配方冻结在 run 的 inputs 中。
5. 共用画面审一次，每语言实际编码成片审一次。八项基本检查以 `config/fast-delivery.json` 为准，实际证据绑定视频/计划/输入哈希；检查必须覆盖清单中的所有实例。静帧检查加源/成片连续帧运动比较，音频用实际听审或明确归因的模型证据。返工后只重查受影响范围，但新的整体成片仍绑定新哈希，不能复制旧通过。
   视觉精致度另填 `visual_finish`，按 [质量标准](../contracts/quality.md) 以正常播放判断，3/5即可接受；轻微纹理/颗粒/接缝记录 minor，避免无限放大追求无差异。major/critical、基本检查失败和未审仍阻断。
6. 原生时轴本地配方用 `fast-register RUN inputs/recipe.json` 冻结输入、产物和审核模板；填写真实的 `review/fast-review.json` 后执行 `quality → deliver`。模板和自动检查不提供人工观察。既有标准合成路线继续用 production，选 fast 不使旧严格门禁自动通过。
7. 交付同步保留源片、成片、配方、依赖、哈希、审核和费用。知识提炼、源解析快照进入 `state/deferred-delivery` 待维护，状态如实为 pending。该目录是持久待办，不表示有后台执行器。维护时处理 reflect/source-save，再核验并关闭待办；交付不等待全库审计。

## 边界

可放宽字体、细微背景修复与装饰样式。漏译、明显英语残留、箭头断层、动作拖影/变速、音轨丢失、不同步与缺失证据仍阻止通过。快速基本审核、严格视觉保真、独立审核和用户验收分别报告。

每次记录本地阶段计时，并另记端到端墙钟、实现/维护时间、供应商等待、人工授权等待。首次实现耗时不能冒充以后每条视频的制作耗时；三语言旧任务与单语言修复的对比须说明范围不同。

## 快速模式的知识与分类

快速制作沿用 [信息载体合同](../../knowledge/rules/content-led-localization-v1.md)。新请求在 fast-register 前完成 routing_assessment 与全部需译人声（包括旁白）；登记同时生成 plans/<id> 的计划/正文/输入快照，work-packet 返回冻结知识及使用反馈待办。knowledge-use 如实记录采用或未采用。旧快速计划显示 legacy_missing_re_register 时，重新登记现有配方/输出即可补新记录；不能声称旧选择已有依据、不能由此继承质量或重发付费任务。
