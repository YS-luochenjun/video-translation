# 近期经验审查

用于用户要求检查最近会话、沉淀临时经验和优化项目。知识采用[知识合同](../contracts/knowledge.md)，日常增量采用[经验总结任务](knowledge-sweep.md)；本流程不发起制作或平台回传。

1. 核对仓库、分支和已有修改；使用doctor验证的Python。列出相关近期聊天后逐个读取真实内容，记录读取范围、当前状态、原片/语种及证据路径到work。会话标题、完成通知和平台入库成功只能定位证据，不能证明媒体质量。活跃会话的中间结果保留待验证，不代其结案。
2. 读取knowledge-queue、hooks status及实际候选正文。把观察、原因假设、修复变量、对照结果和限制分开；同源多语和多次返工不计为独立复验。源限定结论沿原scope建案例，未完成正常播放/听审明确保留。短辅助素材不凭文件名当作第二条完整原片，核对原时长、帧覆盖和来源身份。
3. 先检索现行方法和技能。同义同范围补充原方法；非同义不合并，重复总结也不创建新技能。确定性的工程故障优先修到代码并增加必要回归；测试证明状态与去重行为，不证明真实画质、翻译或发音。临时网络、宿主审批和上传事件留在work/state；只有可复现根因与验证后的修复才形成工程知识。
4. 证据足够时knowledge-promote，再knowledge-review登记明确采纳部分。其余保留具体缺口，例如需核对最终编码alpha、原生首末帧或完整听审；不写笼统“再总结”。Hook故障保留原检查点，可prepare/apply接续，实际回执注明推理方式。独立案例需携带必要证据；旧run路径不是证据文件本身。
5. 技能及文档仅保留决策入口，模型/别名/预算等值引用现有配置。检查修改的技能是否仍与当前合同一致。原型脚本没有输入说明、失败边界和验证时保留为未纳入项，不把活跃制作脚本直接升级为公共默认能力。
6. 完成相关测试、check、knowledge-audit和仓库检查；流程图引用源变化后同步引用。保存已处理来源数、采纳/待证实项、剩余队列和检查回执。授权commit/push时，逐文件审查并包含知识正文、索引、案例manifest及其依赖；不提交运行数据、凭据或未审原型。提交后核对远端结果及工作区剩余变化，不从本轮完成声称全量历史已审完。
