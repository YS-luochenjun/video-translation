# 定时存储整理

职责：按存储合同释放可安全回收的本地空间。默认每天洛杉矶时间18:30由独立应用定时任务唤醒；不等待经验总结成功，也不在Fireplay巡检中执行全局清理。

1. 读AGENTS.md与agent/contracts/storage.md、config/maintenance.json，使用doctor验证的Python。读取storage-report、storage-plan和已有state/maintenance回执，先记录当前实际占用。
2. 每轮最多处理3个明确已结案run。核对对应真实外部提交/绑定、必要经验记录和当前成片；当前活动、缺少交付、未知费用、质量异议或引用未保全时保留并记原因。不能以聊天空闲或文件年龄推断已结案。
3. 对已核实完成的run执行maintain RUN --close，由现有执行器完成保全、预览和指纹删除。单独删除必须run-preserve → run-delete预览 → --execute --expect本次指纹。失败不force、不重建账本、不清除锁。
4. 已登记且未变化、未被引用的可重建缓存和普通空目录按现有门禁整理。旧完整视频仅用明确选择清单并保全知识证据后处理。未登记旧文件先分类，不按年龄/扩展名批量删除。
5. 复查知识独立性和必要包完整性，记录实际删除字节、磁盘变化及暂缓项到work/state。保全可能增加持久占用；以实际净变化报告，不将缺失文件计作释放空间。

本任务不接需求、不制作或回传视频、不提炼/推广方法，不删除必要知识、原始账本、当前交付和安装资产；不递归清空work/outputs/media/state。知识记录不足则转为待补记录，交独立经验任务处理，保留现场。只报告真实空间释放、新的容量风险、明确失败或需要用户决定；相同阻塞保持安静。不自动commit/push。
