# 从诊断版本完成正式交付

适用：已有预览、底片或付费结果，却还没有正式交付；或修复一处问题后准备再生成整套材料。先运行 `work-packet RUN`，按 `next_action` 和现有 blocker 继续。它是导航；实际命令重新验证输入、预算和质量门禁。

## 每轮只推进当前缺口

| 现场 | 下一步与完成条件 |
| --- | --- |
| 源实例未完成 | 补实际文字、人声与时间覆盖；缺证据继续 pending。 |
| 底片已有但未放行 | 生成该底片的中性证据并记录逐实例观察；通过后 release，再 plan。 |
| 只有诊断 MP4 | 将已检查的底片、混音、字层及其来源绑定回 inventory，建立正式 plan。诊断 MP4 不能直接改名交付。 |
| 模型生成中／提交不明 | 查询原 taskId／核对原回执。未知费用继续占位；本地独立检查继续进行。 |
| 正式候选已有 | 先查看已有证据和质量失败；缺观察就补观察，只有需要改变制作输入的缺陷才返工。 |
| 当前 quality 通过 | 直接 deliver；核对 package、case、inbox，再刷新 delivery-index。 |

未完成逐实例观察、声音比较或正式计划时，说明具体剩余工作，由当前 Agent 继续执行。只有真实用户反馈或必要偏好缺失，才描述为等待用户判断。

命令返回后先读JSON的state、failures和恢复提示。production/batch-run处于needs_inventory、needs_review或needs_attention时，CLI退出码2表示内部工作尚未完成；quality/caption-check未通过也返回2。按具体缺口继续解析、实际审核或有界修复，不能仅凭这个退出码停止在预览，更不能把待审改成通过。

## 修复前先冻结改变的变量

在现有 repair 配方的 reason 或逐实例 issue 中写清：实际症状、帧／时间、区域、这轮改什么、预期影响、如何反证。沿用原有记录，不另写平行进度日志。先选能覆盖症状的原尺寸短区间；再按当前门禁检查完整底片与实际编码成片。

动态纹理、手部、蝴蝶结、转场和水印交叉区，分别看源片、底片、字层和成片。正文边界与光晕／模糊入场边界可能不同；供体不能跨姿态或产品切镜。局部干净仍需检查运动、接缝和品牌保护。

复用前检查内容哈希、参数、实现版本及质量异议。同源解析、未变配音与合格底片可按各自入口复用；新语言的定稿、时轴和成片审核重新建立。音频审核回执、费用对账不改变制作素材，应更新审核和账本，保持渲染缓存；选中的模型媒体、译文、字层或混音改变则重新生成受影响内容。

现有本地修复配方的次数／耗时限制仍有效。一次性脚本应先接入 [修复配方](repair-recipes.md)，其自带循环不能重置整个任务的返工限制。到达既有限制后记录未通过原因、剩余缺陷和下一条可验证路线；不得靠生成更多未审预览代替收口。

## 结案后的保留

| 内容 | 去向 |
| --- | --- |
| 实际交付、采用的底片／声音／字层、当前完整审核 | 独立交付包，按业务复用需求保留。 |
| 失败经验 | 独立知识案例：原始观察、改变的变量、必要原尺寸对照；运动／闪烁需连续区间，声音问题需声音证据。 |
| 任务号、未知费用、质量异议 | 保留原账本及独立记录，直到各自门禁允许处置。 |
| 重复旧比较图／可重建中间材料 | 核对引用与保全后进入清理预览；执行沿用授权和预览指纹。 |
| ASR/OCR 等模型、工具与安装依赖 | 独立于普通临时文件管理，避免删除后重复下载和安装。 |

具体可执行清理范围以 [存储布局](../contracts/storage.md) 和预览结果为准。当前 run-prune 主要处理旧比较图片，不是任意中间视频淘汰器。未知费用会阻止清理；不得为省空间抹掉占位。新案例保留精选证据，生产全帧复查依赖交付／恢复包，二者用途各自明确。
